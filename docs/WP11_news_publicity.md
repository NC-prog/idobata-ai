# WP11 — 広報（お知らせの紹介）と「役」の骨組み（Claude Code 向け作業指示）

対象機: 7560（standalone、main 34921f6 以降）。ブランチ `feature/wp11-news`。
目的: 市町のサイトの新着情報・お知らせから、住民に広く関係するもの（通行止め・断水・休館・イベント・募集・防災・ごみ収集の変更など）を
来訪者の同意を取って 1 件紹介する。紹介のときは画面がニュース番組の構図になる（アバターが右へ寄り、左に記事の画像、
アバターの足元に記事ページの QR コード、15〜20 秒の要約を読み上げ）。あわせて、案内役を「役」の一つとして切り出し、
今後の「ロビーの相談員」「井戸端ファシリテーター」を足せる骨組みを作る。

前提の決定（2026-10-24、Norio）:
- 候補は夜のパック更新で集め、分類と要約も夜に作る（会話中に LLM で要約を作らない）。職員は承認待ちにせず、**自動で出す・職員は止められる**。
- 紹介のきっかけは「用件が終わった後」と「雑談で話題が切れたとき」の 2 つ。1 会話 1 件まで。
- 記事の画像は市町のサイト上の画像だけ。外部サイトの画像は取らない。職員パネルで画像だけ止められる。
- 誰もいないときのサイネージ表示は今回やらない（別の判断）。
- 外向き通信は従来どおり許可ドメインだけ（記事も画像も許可ドメイン内）。会話・音声・映像は出ない。

WP11 は **A → B → C → D** の順。A・B を終えて push してから C。

---

## A. お知らせの収集・分類・要約（kb/ と夜の処理）

### A-1. 収集（`kb/build.py` の「お知らせ」区画）

- `kb/sources/<site>.yaml` に区画 `news` を足す。江田島は `cms/atom/news`・`cms/atom/topics`・`cms/atom/events`（既にある）を
  news 区画として扱い、安芸太田は町のトップページの新着情報・お知らせ・イベントの一覧を調べて同等の入口を見つける
  （RSS/Atom があればそれ、無ければ一覧ページ）。見つからなければ止まって報告。
- 記事 1 件のレコード（`~/idobata-data/kb/<site>/news/<id>.json`。id は URL のハッシュ）:
  `title, url, published(日付。無ければ取得日), body(本文テキスト), image(パック内の相対パス or null), image_src(元 URL),
  category, relevance(introduce|skip), relevance_reason, summary, summary_checks(ok|held と理由), period(開始・終了。日付が取れたときだけ),
  expires_at, status(auto|stopped|priority|held), image_hidden(bool), fetched_at, content_hash, shown_count`
- 画像: 記事ページ内の `og:image` か本文の最初の画像で、**許可ドメイン内**・幅 400px 以上・記事と同じサイトのものだけ 1 枚。
  長辺 1280 に縮小してパックに保存。無ければ null（画面は題名だけの板になる）。
- `--daily` に含める（毎朝 6:00 の差分で新着を拾う）。既存の記事は content_hash が変わったときだけ分類・要約をやり直す（職員が直した summary は上書きしない。`edited_by_staff` を持つ）。
- 期限: `period.end` があればその翌日、通行止め・断水など期間が本文にあればその終わり、どれも無ければ取得から 14 日（`NewsConfig.default_ttl_days`）。期限切れは候補から外す（ファイルは 30 日で消す）。

### A-2. 分類（`kb/news_classify.py`。夜だけ動く）

- まず規則: 題名・本文の語で「紹介しない」を先に落とす（入札・契約・人事・採用試験の結果・議会・例規・統計・公告・入札結果・予算・決算・監査・
  パブリックコメントの結果・ふるさと納税の返礼品の追加 など）。「紹介する」側の語（通行止め・迂回・断水・休館・休止・中止・延期・開催・
  募集・申込・受付開始・接種・健診・検診・避難・警報・訓練・ごみ・収集・停電・イベント・まつり・教室・講座・無料・配布）。
- 規則で決まらないものだけ LLM（7560 の Qwen3-8B、thinking オフ、temperature 0）に「住民に広く関係する案内か」を **introduce / skip** の
  二択で答えさせ、理由を 1 文。入力は題名と本文の先頭 600 字。
- `category` は 通行止め・ライフライン・施設・イベント・募集・健康・防災・ごみ・その他 の 9 つ（`server/context/news.yaml` に語と一緒に置く）。

### A-3. 要約（`kb/news_summarize.py`。夜だけ動く）

- introduce の記事だけ。LLM に **90〜120 字・2〜3 文・話し言葉（案内役の口調。persona.yaml の決まりを渡す）** で書かせる。
  1 文目は「何が・いつ・どこで」、2 文目は来訪者がすること（申込・迂回・持ち物など）。「くわしくは市のホームページで」は書かせない（画面で出す）。
- 読み上げ前の安全装置を**要約の保存時**に通す（dialogue.py の既存の関数を再利用。関数化が要れば切り出す）:
  日付・期限・金額・単位つきの数・支払方法は本文にそのまま有るときだけ／英単語 0／拠点に無い課の名前・課の階の作り話を含まない／
  過ぎた日付をこれからと言わない。1 つでも引っかかれば `summary_checks: held` にして**紹介しない**（職員パネルで直せる）。
- VOICEVOX で合成した長さを測り、15〜22 秒に収まらなければ 1 回だけ短く（長く）書き直させる。それでも外れたら held。
  合成した WAV は保存しない（長さを測るだけ。紹介のときに改めて文単位先行合成で読む）。

### A-4. 完了条件（A）

- 両拠点で `--daily` を手で 1 回回し、記事の件数・introduce/skip の内訳・held の件数と理由を表にして `docs/WP11_result.md` に。
- 分類の妥当性: 両拠点から記事を 20 件ずつ無作為に取り、Claude Code 自身が記事を読んで introduce/skip を付け、機械の判定との一致率を出す。
  一致が 80% を下回ったら規則の語を足して再評価（結果文書に前後）。
- pytest（kb）: 規則の分類、期限の決め方、画像の条件（許可ドメイン外・小さい・他サイト を落とす）、職員が直した要約を上書きしない。

## B. 職員パネル「お知らせ」タブと設定

### B-1. 職員パネル（`/staff/news/`）

- 一覧: 題名・掲載日・分類・状態（自動／止めた／優先／保留(held)）・期限・紹介した回数・画像の有無。状態と分類で絞り込み。保留は件数を赤で。
- 詳細: 要約の編集（保存時に A-3 と同じ安全装置を通し、通らなければ理由を出して保存しない）、**止める／自動に戻す／優先にする**、
  **画像を出さない**（image_hidden）、プレビュー（紹介の画面を横・縦で描いた静止画。エッジのページを `?preview=<id>` で開くだけでよい）。
- 「優先」は次の紹介でその記事を最初に出す（複数あれば掲載日の新しい順）。優先が無ければ、分類の重み（通行止め・ライフライン・防災 ＞ 施設・ごみ ＞ イベント・募集・健康・その他）→ 掲載日の新しい順 → 紹介した回数の少ない順。
- 書き込みは記事の JSON を直接更新（git 管理外）。フロントは起動時と 60 秒ごとに読み直す（手続きナレッジと同じ要領）。

### B-2. 設定（`server/src/config.py` の `NewsConfig`）

`IDOBATA_NEWS=1`（既定 1）、`max_per_session=1`、`summary_min_chars=90`、`summary_max_chars=120`、`speech_min_sec=15`、`speech_max_sec=22`、
`default_ttl_days=14`、`propose_after_business=True`、`propose_in_smalltalk=True`、`image_max_edge=1280`、`reload_sec=60`。

### B-3. 完了条件（B）

- 職員パネルで 1 件を「止める」→ 候補から消える、「優先」→ 次の紹介で最初に出る、要約を直す → 安全装置に引っかかる文は保存できない、が通る。
- pytest（server）: 選ぶ順番、止めた・期限切れ・held を出さない、画像を隠す。

## C. 会話への組み込み（「役」の骨組み・同意・画面）

### C-1. 役（`server/src/roles.py`）

- `Role` dataclass: `name`（reception / publicity）、`prompt_block`（【話し方の決まり】の後ろに足す段落。publicity は「お知らせを一つ読む係」の短い決まり）、
  `actions`（この役で提案できる行為の名前）、`layout`（エッジの構図名 normal / news）。
- 進行役（オーケストレータ）は main.py の状態機械の中に置く（別プロセスにしない）。今回の切り替えは **reception → publicity → reception** の 1 往復だけ。
  役が変わるとき、エッジへ `{type: "layout", mode, ...}` を送り、履歴には定型の一言を残す（WP07 の「定型の一言を履歴に」と同じ）。
- 既存の案内役の決まりは reception の prompt_block に移すだけで、文言は変えない（評価セット 30 問で差が無いこと）。
- 今後の役（相談員・ファシリテーター）は Role を足すだけで済むように、役の選択は `select_role(state) -> Role` の 1 か所に閉じ込める。

### C-2. 提案と同意（`server/context/actions.yaml` に `news` を足す）

- 提案文（固定）: 「ところで、市からのお知らせを一つご紹介してもいいですか？」（安芸太田は「町から」。facility の org から取る）
- 提案のきっかけ（LLM に `<propose:news>` を出させる**のではなく**、進行役が状態で決める）:
  1. 用件の後: 紹介状の保存と bring の案内の後／「ほかに何かありますか」に「ない」に当たる返事／調べる・つなぐの行為が終わって 1 ターン静かなとき。
  2. 雑談: 相手の発話が 2 ターン続けて雑談（既存の判定）で、締めの定型に入る前。
  - 出さない: 紹介状の聞き取りの途中、深刻な打ち明けの定型に入った会話（その会話では以後出さない）、相手が急いでいる語（急いで・時間がない）を言った会話、
    既に 1 件紹介した会話、候補が 0 件のとき。
- 返事の判定は既存の規則（actions.yaml の reply）。はい → C-3。いいえ／無言 5 秒 → 「わかりました。」と言ってそのまま。その会話では再提案しない。
- 来訪記録（visits）に「お知らせを提案した／紹介した／断られた」と記事 id を匿名で足す（本文は入れない）。記事の `shown_count` を増やす。

### C-3. 紹介の流れ

1. 前置き（固定）: 「それでは、{掲載日の言い方（今日・昨日・N月N日）}のお知らせです。」
2. エッジへ `layout: news`（title・image の URL（`/edge/news/<id>.jpg`。image_hidden なら null）・QR の PNG（data URL）・url・category）。
   QR は Python 側で `segno`（BSD-3）で作る（誤り訂正 M、記事 URL そのまま）。`uv add segno`。
3. 要約を文単位先行合成で読む（既存の経路。相槌は出さない）。字幕は要約。
4. 読み終えて 2 秒置いて `layout: normal`。締め（固定）: 「くわしくは、画面の QR コードから市のページをご覧ください。ほかに何かあれば、どうぞ。」
   （QR を見せる時間を取るため、締めの文を言い終えるまでは QR を残し、`layout: normal` は締めの後にする。画像だけ先に消してよい）
5. 紹介の最中に相手が話しかけたら、読み上げを止めて（既存の割り込みの仕組み）`layout: normal` に戻し、通常の応答へ。shown_count は増やす。

### C-4. エッジの構図（`edge/`）

- 横置き: 左 2/3 に画像の枠（object-fit: contain、暗い板、下に題名を 1〜2 行）、右 1/3 にアバター（カメラの注視点を右へずらして胸から上）、
  アバターの足元に QR（一辺 180px）と「市のホームページ」の小さな文字。字幕は従来の位置。クレジット（WP10）は従来どおり。
- 縦置き（本番）: 上 45% に画像の枠と題名、下にアバター（少し小さく）、QR はアバターの右下（一辺 220px）。
- 切り替えは 0.5 秒のフェード。`layout: normal` で元の構図へ。画像の URL は `/edge/news/<id>.jpg` をフロントが配信（avatars・backgrounds と同じ経路、許可の範囲も同じ）。
- `?preview=<id>` でサーバの `/edge/news/preview/<id>` から layout メッセージを受け取り、WebSocket なしでその構図を描く（職員パネルのプレビュー用）。

### C-5. 完了条件（C）

- テキストモードで「国保の手続きを聞く → 紹介状 → 保存」の後に提案が出て、「はい」で要約が流れ、layout の往復がログで確認できる。
- エッジで横・縦のスクリーンショット（WP10 と同じ方法）を `docs/img/wp11_news_{landscape,portrait}.jpg` に。QR をスマホで読めることを人間が確かめる前提で、
  Claude Code は PNG をデコードして URL が一致することを確認（`segno` には読み取りが無いので `pyzbar` か `opencv` の QRCodeDetector をテストだけに使う。本体の依存には入れない）。
- 評価セット 30 問・雑談 10 問・意地悪 30 問に回帰が無いこと（提案が増える分の差は結果文書に書く）。
- 「急いでいる」「紹介状の途中」「深刻な打ち明けの後」で提案が出ないテスト。
