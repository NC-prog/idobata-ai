# WP13 — 会話で使う知識の絞り込み（集めるのは広く、会話で使うのは狭く）（Claude Code 向け作業指示）

対象機: 7560（standalone）。ブランチ `feature/wp13-scope`（WP12 のマージ後に main から切る）。
目的: 8B の脱線を構成で止める。2026-10-24 の実機確認で出た脱線は全部「検索が関係ありそうな文章を拾い、8B がそれを本題にした」型だった
（国保→国保税 Q&A、児童手当→求人の通勤手当、「わかりました」→協調学習の記事、「町から案内ある？」→道の駅のブログ）。
大きいモデルなら無視できる雑音を 8B は無視できない。クロールの広さは「調べる」のために要るので、**集める範囲と会話に渡す範囲を分ける**。
T2 の大きいモデルに替えた後も「ロビーで言ってよい範囲」を構成で担保する意味で残る設計。

前提の決定（2026-10-24、Norio）: 会話の参考資料は、住民が窓口で聞く範囲（手続き・施設・開庁時間・ごみ・防災・行事・子育て・高齢者・健康・暮らし）に絞る。
観光・道の駅・ブログ的な記事は「調べる」（同意付き）のときだけ。求人・入札・人事・議会・例規・統計・公告・予算決算は集めない。

WP13 は **A → B → C → D** の順。

---

## A. 区画に用途を付ける（`kb/sources/<site>.yaml`、`kb/build.py`）

- seeds の各区画に `use:` を足す。値は 3 つ:
  - `dialogue` — 会話の参考資料に使う（既定。書かなければこれ）
  - `lookup` — 「調べる」のときだけ使う。会話の毎ターンの検索には出さない
  - `exclude` — 集めない（クロールもしない）。seeds から消すのと同じだが、消した理由を残すために `use: exclude` と `why:` で書いてよい
- チャンクの metadata に `use` を持たせ、LanceDB の検索でフィルタできるようにする（パックの形式が変わるので、`manifest.json` に `format: 2` を入れ、古い形式のパックは全部 `dialogue` 扱いで読める互換を残す）。
- 区画の中でも URL の型で用途を変えたいことがある（町のサイトの `/soshiki/` の中に求人の記事がある、など）。`use_rules:`（URL の正規表現 → use）を区画に書けるようにし、
  題名の語（「求人情報」「入札」「議会」「例規」「統計」「人事」「公告」「予算」「決算」「監査」「パブリックコメント」）でも `exclude` にする既定の規則を `kb/scope_rules.yaml` に置く。
- 両拠点の seeds を Claude Code が分類して表にする（区画・URL・use・理由）。**表は結果文書に載せ、Norio が見て直せるようにする**。迷うものは `dialogue` ではなく `lookup` に倒す。
  目安:
  - dialogue: 課のページ（/soshiki/ の案内）、くらし・子育て・高齢者・健康・ごみ・防災・施設・開庁時間・手続きナレッジの出典・行事カレンダー・社協の相談窓口
  - lookup: 観光協会・あきおおたから・道の駅・dive-hiroshima・図書館の新着・社協のブログ的な記事・広報紙・求人の一覧（「求人がある」ことは言える）
  - exclude: 入札・契約・人事・採用試験・議会・例規・統計・公告・予算決算・監査・パブリックコメントの結果・町長室・サイトの管理ページ
- news 区画（WP11）は今までどおり別扱い。

### A-1. 完了条件

- 両拠点で全体のビルドを回し、`dialogue` / `lookup` / `exclude` のページ数・チャンク数を前後で表にする。
- 古い形式のパックを読んだときに落ちないテスト。`use` でフィルタする検索のテスト。

## B. 来訪者の発話の型分けと、型ごとの検索範囲（`server/src/knowledge.py`、`dialogue.py`）

- 発話の型を規則で決める（LLM を使わない。`server/context/intents.yaml` に語を置く）:
  `procedure`（手続きの語: 別名表・対象一覧・手続きナレッジの name/aliases）／`facility`（場所・階・開庁・駐車場・トイレ・設備の語）／`event`（行事・イベント・催し・まつり・教室・講座・いつ・今週末）／
  `tourism`（観光・名所・温泉・道の駅・おすすめ・見どころ・食べる）／`weather`（天気・雨・暑い・寒い）／`smalltalk`（上のどれでもなく、質問の形でもない。短い返事・報告・相槌を含む）／`other`（上のどれでもない質問）。
  1 発話に複数当たれば `procedure > facility > event > tourism > weather > other > smalltalk` の優先。
- 型ごとに「毎ターンの検索で渡してよい区画と件数」を `KnowledgeConfig.scope_by_intent` に持つ:
  - procedure: 承認済みの手続きナレッジ＋固定事実。**パックは渡さない**（承認済みが無いときだけ `dialogue` 区画を上位 2 件まで）
  - facility: 固定事実だけ（パックは渡さない。設備の作り話の安全装置は従来どおり）
  - event: `dialogue` 区画の行事カレンダーと news の introduce 記事。上位 3 件
  - tourism: 渡さない。「調べてみましょうか？」の提案を優先する（`lookup` 区画はそのときに使う）
  - weather: 天気だけ
  - smalltalk: 渡さない（8 字以下の規則を一般化してこれに統合する）
  - other: `dialogue` 区画の上位 3 件。ただし類似度の足切りを今より厳しく（下の B-2）
- 「調べる」（lookup.py）は `dialogue` と `lookup` の両方を検索する（今までの範囲を保つ）。

### B-1. 承認済みの手続きが当たったターンはパックを渡さない

今日の「国保→国保税 Q&A」はこれで消える。承認済みのレコードに無いことを聞かれたら（例: 国保税の額）、「市の案内では」の範囲で答えて、残りは担当の課へ。

### B-2. 足切り

- `other` と `event` の資料は、いまの条件（cos 0.86 以上、または 0.80 以上かつ BM25 5 位以内）に加えて、**発話の名詞（2 文字以上）のどれかが資料の題名か本文の先頭 200 字に含まれる**ことを条件にする。短い発話で名詞が無ければ渡さない。
- 渡した資料の題名を、今までどおり `[出典]` に出す（脱線の数え方に使う）。

### B-3. 完了条件

- 型分けのテスト（各型 5 例、優先の例、短い返事）。
- 毎ターンのログに「型: procedure / 渡した資料: 承認済み 1・パック 0」のように 1 行出す。

## C. 評価（脱線を数える）

- 「脱線」の定義: 渡した資料（`[出典]`）の題名が、発話の型・語と無関係（人が見て判定。補助として、題名と発話の名詞の重なりが 0 かつ型が合わない）。
- 評価セット 30 問・手続き 100 問・雑談 10 問・意地悪 30 問を **main と WP13 で同じ LLM・同じ時刻帯に**回し、次を前後で表にする:
  脱線の件数／資料を渡したターンの数／応答の正答（既存の補助判定）／音声開始までの時間（資料が減れば速くなるはず）。
- 10/24 の実機のログの 4 つの脱線（国保税・求人・協調学習・道の駅）をテキストモードで再現し、全部消えていることを確認（会話の流れごと `tests/eval/cases_regression_1024.yaml` に残す）。
- 回帰で正答が下がった問いがあれば、その問いが必要としていた資料がどの区画にあったかを調べ、`use` の付け方か型分けの語を直す（安全装置や足切りを緩めて直さない）。

## E. 用件の聞き分け（複数の手続きが同程度に当たったら、来訪者に 1 問だけ聞く）（2026-10-24 追記）

### E-1. いつ聞くか

- 発話の型が procedure で、手続きナレッジ（承認済み・下書きとも）と別名表の照合で 2〜4 件が同程度に当たる（1 位と 2 位の点差が小さい。しきい値は `ProcedureConfig` に）。
  例: 「国保」→ 加入・脱退・保険証の再交付・国保税／「手当のことで」→ 児童手当・児童扶養手当・介護
- 1 件に絞れるときは聞かない。紹介状の聞き取りの途中、深刻な打ち明けの定型の後、急いでいる語のある会話では聞かない。
- 1 つの用件につき 1 回まで。聞き分けの 1 問と紹介状の intake（最大 3 問）は合わせて 3 問に収める（聞き分けで決まったら intake を 1 問減らす）。

### E-2. 質問の作り方（LLM を使わない）

- 当たった手続きの name（対象一覧の when があればその言い方）を並べた定型: 「{共通の語}のことですね。{A}か、{B}か、{C}か、どちらでしょう？」。
  選択肢は 3 つまで、4 件以上なら上位 3 つ＋「ほかのこと」。定型文は `context/actions.yaml` に `clarify` として置く。
- 字幕には選択肢を番号付きで出す（読み上げは番号を言わない）。

### E-3. 返事の判定（規則）

- 別名表・name の語との一致、順序の語（最初の・二つ目・最後の・一番目…）、「ほか」。合わなければ 1 回だけ「すみません、{A}か{B}か、どちらでしょう？」と聞き直す。
  それでも決まらなければ「手続きの詳しいことは担当の課でご案内します」＋紹介状の提案（担当課は未特定のまま）。
- 返事待ちの間は、既存の「返事待ち」の VAD・言語固定を使う。

### E-4. 決まった後

- 決まった 1 件だけを資料に渡す（B-1 の道に合流）。承認済みならその中身、下書きなら「担当の課でご案内します」。
- 話題の手続きのカウント（WP11 のきっかけ）は決まった 1 件で数える。
- 文字記録と来訪記録に「聞き分けた（候補 n 件 → 決まった id）」を 1 行（本文は入れない）。

### E-5. 確認

- テキストモードで「国保のことで」「手当のことで」「保険証」の 3 つが聞き分けに入り、返事で 1 件に決まること。「国保に入りたい」のように 1 件に絞れる発話では聞かないこと。
- 手続き 100 問で、聞き分けに入った問いの数と、その後の正答を表に（聞き分けが増えすぎていないか: 100 問中 15 問を超えたらしきい値を見直して報告）。
- 10/24 の 4 つの脱線の再現は、聞き分けありでも 0 であること。

止まる条件: 聞き分けに入る問いが 100 問中 25 問を超える／返事の判定が人間の見立てと 8 割未満しか合わない（結果文書に返事の例を 20 件並べて）。

### あわせて（2026-10-24）

- 手続き 100 問の 58 番（犬を飼う→市民課）: 資料 0 件・承認済み無しのときに、LLM の課名が「規則で決まらない課を捨てる」安全装置を通り抜けた理由を調べて直す。
- 「バス停」の引き上げは、題名に路線・時刻・乗合のどれかが無ければ上げない（浜田省吾のバス停は lookup へ）。
- 評価の回し直しは E と一緒に最後に 1 回。
