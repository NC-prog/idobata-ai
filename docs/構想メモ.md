# 井戸端AI（仮）構想メモ v0.5

ローカルAIの価値を体感させる「役所の総合窓口アシスタント」  
富士製作所合同会社 / 2026-10-18 / 壁打ち用ドラフト

---

## 1. 目的

- **ローカルAIの良さを「見て・触って」わかる形にする。** 映像・音声・会話が役所の建物から一切出ない。だから窓口で打ち明け話ができる。クラウドAIでは「外のサーバーに送られます」と言った瞬間に傾聴は成立しない——これが訴求の核。
- 江田島市・安芸太田町の両方に同じものを置き、**役所を「用がなくても人が集まる場所」にする**。
- The Meet 2026 の横展開素材として、首長・議会・住民に「AIが来ると役所がどう変わるか」を一目で伝えるデモにする。

## 2. コンセプト：「相談窓口」ではなく「井戸端」

既定の態度を「用件を聞く」ではなく「居てもらう」に倒す。用件があれば受ける。なくても追い返さない。

| 来訪者 | 井戸端AIのふるまい |
|---|---|
| 涼みに来た高齢者 | 茶飲み話。畑・天気・昔話。急かさない |
| 育児で悩む母親 | 傾聴が主、助言は求められてから。希望すれば担当課へ「紹介状」 |
| 通知書を持って困っている人 | 紙をカメラに見せてもらい、どこに何を書くかを指さし解説 |
| フェリーで来た観光客・外国人住民 | 多言語で案内。窓口の人手不足を補う |
| 用はないが寄った人 | 「今週末、〇〇で秋祭りですよ」と今日のまちの話題 |

### 設計上の3原則

1. **記憶は本人が「残していい」と言ったものだけ。** 傾聴モードの会話は原則その場で消える。
2. **部局連携は「紹介状」の形。** AIが手続きを進めるのではなく、本人の言葉を要約した「ご相談メモ」（内容・急ぎ度・希望する連絡方法）を担当課のキューに入れ、職員が人として受け取る。
3. **「たわいのない話」の循環には同意ゲート。** 「みんなに言っていいよ」と言われた匿名化済みの一言だけを「今日の小ネタ」プールに入れ、次の人に伝える。

## 4. システム構成

### 3層構造：エッジは「顔と体」、フロントAIは「目・耳・口」、バックエンドAIは「頭」

AIワークステーションにカメラ・マイク・スピーカー・ディスプレイを直結せず、間に安価なWindows機（またはミニPC）を置く。理由：音声・映像デバイスとキオスク表示はWindowsのほうが扱いやすく、現場での交換・増設がGPU機に触らずに済む。1台のフロントAIが複数のエッジ（ロビー、支所、公民館）を受け持てる。

```
[窓口] エッジ機（Windows ミニPC、GPU不要・内蔵グラフィックで可）
  ├ カメラ・マイク・スピーカー・ディスプレイ（必要ならタッチ）
  ├ ブラウザをキオスク全画面：three.js + three-vrm でアバター描画
  ├ 音声・映像をフロントAIへ送出（WebRTC または WebSocket。映像は検知用に縮小・低fps）
  └ フロントAIからの駆動イベント（発話音声、口パク・表情・視線、字幕）を受けて再生
          │ 現地LAN：エッジとフロントAI機はスイッチングハブで直結（同一セグメント、庁内ネットワークとは分離可）
          ▼
[現地] フロントAI機（12〜24GB GPU：Z2 A2000 12GB / 3650 RTX 3090 24GB）
  ├ 人物検知（YOLO）＋顔向き推定（軽量）
  ├ VAD → 音声認識（Qwen3-ASR ストリーミング）
  ├ TTS（VOICEVOX 日本語 / 多言語は別エンジン）→ 音声＋口パクタイミングをエッジへ
  ├ 会話状態（セッション、同意フラグ、言語、どのエッジか）
  └ 複数エッジの多重化
          │ Tailscale（富士製作所tailnet）／将来は現地LAN内
          ▼
[バックエンド] Dell Pro Max T2（RTX PRO 6000 Blackwell 96GB）
  ├ LLM（gpt-oss / vLLM）：ペルソナ、傾聴、紹介状生成、部局ルーティング判断
  ├ VLM（Qwen3-VL級）：持参書類の読解
  ├ RAG（Ruri v3 埋め込み）：市サイト・広報・イベント・FAQ
  └ 紹介状キュー → グループウェア連携（CSV／メール）
```

- エッジ機：既存のWindows機で足りる。目安は下表。保存するものは何もなく、盗難・故障時もデータが残らない。

| 項目 | 最低 | 推奨 | 備考 |
|---|---|---|---|
| OS | Windows 10 22H2 | Windows 11 | Windows 10はサポート終了済みのため、庁内のセキュリティ方針上は11 |
| CPU | 第8世代 Core i3 相当 | 第10世代以降 Core i5 相当 | 仕事はブラウザ描画＋音声・縮小映像の送出のみ。Celeron／Atom級は避ける |
| GPU | 内蔵（WebGL 2.0対応） | 内蔵で可 | VRM 1体・1080pの描画はIntel UHD 620級で足りる。dGPU不要 |
| メモリ | 8GB | 16GB | ブラウザのキオスク常駐で十分 |
| ストレージ | SSD 64GB以上 | SSD | HDDは起動と更新が遅い |
| ネットワーク | 有線LAN | 有線LAN | エッジとフロントAI機の間はスイッチングハブ（ギガビット、アンマネージドで可）で直結。Wi‑Fiは音声の途切れの原因になるので避ける |
| カメラ | USB 720p/30fps | USB 1080p、広角、USB‑C延長可 | 画角は窓口前2〜3mが収まるもの。映像はエッジで縮小して送るのでカメラ性能は不問 |
| 音声 | USBスピーカーフォン | AEC内蔵のUSBスピーカーフォン（townhallで使ったAvaya B109級） | 機器側AECがあれば SpeechGate の後マージンを詰められる。内蔵マイク＋別スピーカーの組合せは回り込みが出やすい |
| 表示 | HDMI 1080p | 縦置きできる大型モニタ、必要ならタッチ | アバターは縦長のほうが「人がいる」見え方になる |
| 運用設定 | スリープ無効、自動ログオン、ブラウザのキオスク全画面を自動起動 | 同左＋電源復帰時の自動起動（BIOSのAC Recovery） | Windows Update の再起動時刻を閉庁時間に固定 |

- ブラウザのカメラ・マイク取得（getUserMedia）はセキュアコンテキストが必須。エッジ上の小さなローカルサーバ（localhost）からページを配信する形にすれば、HTTPS証明書なしで済む。フロントAIへのWS接続先だけ設定ファイルで持つ。
- フロントAIのGPU予算：YOLO＋顔向き＋ASR 0.6B〜1.7B＋VOICEVOXで12GBに収まる見込み。3650（24GB）ならTTSの多言語モデルも同居できる。
- エッジ⇄フロントの契約（API）を先に固め、エッジ側はブラウザだけで完結させる。これでエッジ機のOSに依存しない（Windowsでもモニタ内蔵のサイネージ端末でも同じ）。
- バックエンドはT2到着（12月初旬）までは3650や7560で代替し、縮小構成で動かす。
- **デモ時の売り文句：** 「このケーブルを抜いても動く」。ネットワークから物理的に切り離して会話を続けるデモを演出に組み込む。

### 音声スタック

| 役割 | 採用（本命） | 備考 |
|---|---|---|
| 音声認識 | **Qwen3-ASR**（0.6B / 1.7B、Apache-2.0） | 30言語超の自動判定。公式はvLLM対応。townhall-assistant で実績あり：Silero VADで発話区間ごとに切って `/v1/audio/transcriptions` に投げる方式で、発話終了→字幕表示の体感約0.9秒（1.7B、vLLM、VRAM約13GB）。井戸端AIもまずこの方式で始め、逐語ストリーミング（因果塔 qfuxa/qwen3-asr-0.6b-streaming）は「相手が話している途中で頷く」演出が欲しくなった時に検討。townhallの `ja` 以外を捨てる言語フィルタは多言語対応のため外す |
| VAD／割り込み | Silero VAD | 相手が話し出したらTTS再生を即停止 |
| TTS 日本語 | **VOICEVOX** | キャラクター性の一貫性のため維持。音素タイミングを口パクに流用。**音源ごとの利用規約（公共利用・改変）を要確認** |
| TTS 英・中 | **Qwen3-TTS**（0.6B / 1.7B、Apache-2.0） | 日・英・中・韓ほか10言語。ストリーム開始約100ms。**ベトナム語は非対応** |
| TTS ベトナム語 | **VieNeu-TTS**（越・英越バイリンガル、Qwen3バックボーン） | 越専用。代替候補：Confucius4-TTS（NetEase Youdao、14言語で越・日を含む）。**ライセンス要確認** |
| 声の統一 | 言語が変わると声が変わる問題 | ①言語ごとに「同じキャラの別の声」と割り切る、②Qwen3-TTSのゼロショット複製でVOICEVOX声に寄せる、のどちらか。まず①で進める |

### アバター

- **three.js + @pixiv/three-vrm（MIT）** を本命。理由：Claude Code が最も安定して書けるのがTypeScript/Web。配信は「URLを開くだけ」なので江田島・安芸太田で同一物を無改変で動かせる。
- アバター作成は **VRoid Studio**。季節衣装はVRMのテクスチャ／モデル差し替えで対応（春夏秋冬＋祭り）。
- **背景も自治体ごと・季節ごとに差し替える。** 江田島なら海と牡蠣筏や能美の桜、安芸太田なら三段峡や温井ダムの紅葉、といった土地の景色を、three.js の背景（静止画・ゆっくり動くパノラマ・簡易な3D）として読み込む。衣装と背景は「テーマ」としてまとめて切り替え（例：`etajima/spring`、`akiota/autumn`、`akiota/festival`）、職員パネルから手動でも、暦で自動でも変えられるようにする。背景素材は自治体提供の写真か、市民から募る。
- 口パク：VOICEVOXのクエリから音素タイミングを取得し、ブレンドシェイプを駆動。多言語TTSは音量包絡ベースの簡易口パクで妥協。
- 視線・顔向き：顔向き推定の結果でアバターの視線を来訪者へ向ける（F1の①）。
- 3D空間演出（井戸端の背景、天候を映す窓）まで欲しくなった段階で **Godot 4（MIT）** へ移行を検討。最初からGodotにする理由は現状なし。
- Unity は不採用（ライセンス・コード生成との相性）。

## 5. 個人情報の扱い方針

- 映像：検知・顔向き推定にのみ使い、フレームは保存しない。顔識別（個人特定）はしない。
- 音声：ASRの入力として処理後に破棄。録音保存なし。
- 会話：セッション終了で消去が既定。残るのは「紹介状」として本人が同意したものと、「小ネタ」として本人が同意した匿名の一言のみ。
- 書類画像：VLM処理後に破棄。
- 外部送信：なし。市のサイト・広報の取り込みは職員側のバッチで行い、窓口機はインターネットに出ない。
- 掲示：窓口に「この会話は建物の外に出ません／残したいものだけ残します」を日本語＋多言語で掲示。これ自体がローカルAIの説明になる。

## 6. 部局連携の実装

- 紹介状スキーマ（案）：`相談種別 / 本人の言葉（要約）/ 急ぎ度 / 希望する連絡方法 / 言語 / 受付日時 / 窓口端末ID`。氏名・連絡先は本人が言った場合のみ、本人確認のうえ記載。
- 安芸太田：サイボウズ Office 10（パッケージ版）の制約により、CSV取り込みまたはメール通知。次年度Garoon移行後はREST API。
- 江田島：市のグループウェア仕様に合わせる（要ヒアリング）。
- 職員側UI：既存のダッシュボードに「紹介状キュー」タブを追加し、受領・担当割当・完了をつける程度。

### 機体と実行プロファイル

- **開発機＝デモ機は Dell Precision 7560（A5000 16GB、ネイティブUbuntu 26.04.1）。** 「持って行って、その場で動く」が売り文句なので、開発機をそのまま持ち回りデモ機にする。WSL2は使わない（NAT越しのWebSocket、スリープ時の停止、ドライバ並びのずれ、という運用上の地雷があり、デバイス直結の問題が消えた今は利点がない）。
- 3650（安芸太田）・Z2（江田島）は同じソフトを設定だけ変えて置く拠点設置機。差は `.env` の役割とバックエンド接続先だけにする。
- プロファイルは2種類：
  - **standalone**：7560単体でエッジ＋フロントAI＋バックエンドを同居。16GBなので LLM は Qwen3 8B級の AWQ（5GB前後）に落とし、ASR は Qwen3-ASR-1.7B（重みは4GB弱。townhall の13GBは `gpu-memory-utilization 0.15` の割り当て値で実需ではない）、TTS・YOLO11-pose と同居。VLM（紙を見せる）は省くか小型。エッジ役は7560上のChromium＋内蔵カメラ・マイクで兼ねる。首長室で「ケーブルを抜いても動く」をやるのはこれ。
  - **site**：フロントAIのみ現地機で動かし、LLM・VLM・RAG は Tailscale 経由で T2（届くまでは3660＋A4500）へ。3650の24GBなら多言語TTSも現地に置ける。Z2の12GBでもフロント分だけなら収まる。
- 7560のストレージ：UbuntuはSN7100（1TB）側。モデル・データは別ボリュームに置く前提で、SN810（2TB、Windows用）の空き領域を切り出して `/workspace` 相当のデータ用ボリュームにし、`~/.cache/huggingface` と `~/idobata-data` をそこへ向ける（Z2の `/workspace` と同じ考え方）。

## 8. townhall-assistant からの移植

Prudential向け [NC-prog/townhall-assistant](https://github.com/NC-prog/townhall-assistant)（Windowsサイネージ機＋RTX PRO 6000の2層、Python 4,900行、テスト・運用手順書あり）を母体にする。前身の受付ボットにあった `camera_client.py`（YOLOv8＋BBoxサイズ＋滞在時間）はコードが残っていないため、新規に書く。

### モジュールの振り分け

| townhall のモジュール | 井戸端AIでの行き先 | 扱い |
|---|---|---|
| `unity/`（Unity＋Live2D） | エッジ | **置き換え**：three.js＋three-vrm のWebページへ。Live2Dモデルはライセンス上リポジトリ非公開が必須で、市所有の成果物として渡せないため、VRM（VRoid）に移る必要がある |
| `unity_bridge.py`（WS 8765：caption / show_panel / hide_panel / set_presenter、bow / talk_start / talk_end） | フロントAI → エッジ | **流用・拡張**：`edge_bridge` に改名し、表情・口パク（音素タイミング）・視線・衣装切替・言語を追加。上りに音声PCMと縮小映像フレームを追加 |
| `audio_input.py`（sounddevice、16kHz/512サンプル） | フロントAI | **入力源を追加**：ローカルマイクに加え、エッジからのWS音声ストリームを同じインターフェースで受ける |
| `speech_gate.py`（TTS再生中はVADに流さない、後マージン0.7秒） | フロントAI | **そのまま**。窓口のスピーカー・マイクはAECが効かない前提なので必須。割り込み（バージイン）を入れる場合はゲートを「TTS中も聞くがエコー区間を捨てる」方式に変える必要があり、P1では割り込みなし＋ゲート維持で始める |
| `vad.py`（Silero、ソフト分割） | フロントAI | **そのまま** |
| `asr_client.py`（Qwen3-ASR、コンテキストバイアシング二層） | フロントAI | **流用**：静的コンテキストにアジェンダ用語の代わりに地名・施設名・課名・行事名を入れる。`ja` 以外を捨てる言語フィルタは外し、検出言語をセッションへ渡す |
| `tts_client.py`（VOICEVOX、graceful degradation） | フロントAI | **流用＋言語ルータ**：検出言語で VOICEVOX / Qwen3-TTS / VieNeu を振り分ける層を上に被せる |
| `caption_feed.py` | フロントAI | **流用**：字幕はエッジと職員パネルの両方へ |
| `session_manager.py`（アジェンダFSM、quiz / chat モード、1,559行） | バックエンド | **書き直し**：会議進行FSM → 来訪者対話FSM（IDLE → NOTICE → GREET → LISTEN ⇄ TALK → REFER_CONFIRM → REFER → BYE）。quiz モードは「地元クイズ」として、chat モードは傾聴ペルソナとして中身を残す |
| `announcer.py`（テンプレート発話、friendly / formal） | バックエンド | **流用**：挨拶・季節の決まり文句・同意確認文はLLMを通さずテンプレートで低遅延に返す（受付ボット由来の知見） |
| `summarizer.py`（ローリング要約 → 発表要約 → 議事録） | バックエンド | **改造**：「紹介状」生成に転用。ローリング要約の仕組みをそのまま使い、同意後に構造化出力へ |
| `llm_client.py`（vLLM Gateway、直接ポートへのフォールバック） | バックエンド | **そのまま** |
| `web_panel.py`（FastAPI、オペレーターパネル） | バックエンド | **転用**：職員用パネル（紹介状キュー、今日の小ネタ承認、衣装切替、言語状態） |
| `config.py`（frozen dataclass集約） | 全層 | 踏襲 |
| （なし） | フロントAI | **新規**：`camera_client`。YOLO11-pose 1モデルで人物検出と顔向き（鼻・両目・両耳のキーポイントの対称性で正面判定）を兼ねる。状態遷移 NONE → PRESENT（BBoxサイズ） → DWELL（2〜3秒滞留） → FACING（正面）がF1の①②③に対応。ByteTrackの一時トラックIDで同一人物への再挨拶を数分抑止、IDは保存しない |
| （なし） | バックエンド | **新規**：VLMクライアント（紙を見せる）、RAG（今日のまち）、紹介状キュー→グループウェア連携、多言語TTSルータ |

### 変わらないもの

- 3台構成・外部インターネット不要・同一LAN完結という前提は townhall と同じ。井戸端AIは「サイネージ機＝エッジ」「サーバ機＝フロントAI＋バックエンド」が、現地と本社側に分かれるだけ。
- uv／pytest／mypy strict／config集約／外部呼び出しにタイムアウトとリトライ、という規約はそのまま引き継ぐ。
- VOICEVOX のクレジット表記（「VOICEVOX:四国めたん」等）は窓口掲示にも必要。

### 移植で決めること

- バックエンド1台が複数のフロントAI（江田島・安芸太田）を受ける前提なので、`session_manager` をプロセス常駐の単一セッションから、拠点×エッジのセッションIDで多重化する。
- townhall は RTX PRO 6000 一台に ASR 13GB＋gpt-oss 38GB＋deepseek 19GB＋埋め込み 13GB を同居させていた。井戸端AIでは ASR・TTS を現地フロント（12〜24GB）へ下ろすので、バックエンドの PRO 6000 には LLM・VLM・RAG の余裕ができ、deepseek の代わりに VLM を載せられる。

## 9. The Meet / 横展開での位置づけ（メモ）

- 既存の2案件（江田島：終末処理場AI、安芸太田：問合せRAG・議事録AI）の「上に乗る窓口」として見せる。処理場や議事録のAIは住民から見えないが、井戸端AIは**見える成果物**になる。
- 補助金のIP構造は従来どおり：市所有の成果物＋当社保持の方法論＋非独占ライセンスバック。GPU購入は補助対象外なので、保有機で動く＝「12GBの現地機で動く」こと自体を検証価値として示す。
- 横展開時のメッセージ：「ハードは役所の片隅の1台、頭脳は1台を複数拠点で共有、会話は外に出ない」。
