## 1. A — 手続きナレッジの形式と読み込み

### 1-1. 置き場と形式

- `~/idobata-data/procedures/<site>/<id>.yaml`（1 手続き 1 ファイル、git 管理外。市が育てる成果物）。形式は指示書 A-1 のとおり
  （`id / name / aliases / department / floor / audience / bring / steps / deadline / fee / related / intake / faq / sources /
  status / approved_by / approved_at / staff_note / content_hash`）。足した項目は 3 つ:
  - `when`: 名前・別名に加えて、この語のどれかが発話にあるときだけ当たる（「マイナンバーカード」＋「なくし」で紛失、無ければ申請）
  - `tags`: 紹介状のタグ（`tags.yaml` の統制語彙）
  - `recheck_reason`: 要再確認になった理由
- `bring` は文字列か `{item, when}`（その語が話に出たときだけ紹介状の後に案内する持ち物。WP04 の国保の 2 つの持ち物を移すため）
- コード: `server/src/procedure_kb.py`（読み書き・突き合わせ・承認・再確認）、`server/src/procedures.py`（担当課・聞き取り）

### 1-2. 対話での使い方

| 項目 | 実装 |
|---|---|
| 読み直し | 読むたびにディレクトリのファイルの更新時刻を見て、変わっていれば読み直す（職員パネルの承認・編集が次のターンから効く。再起動不要） |
| 優先順位 | 固定事実（facility、システムプロンプト）＞**承認済み**の手続きナレッジ（【市の案内（承認済み）】、参考資料より前）＞パック＞LLM の一般知識 |
| 担当課 | 承認済みのレコードの `name`（括弧書きを除く）・`aliases` が発話にあればその `department`。残りの発話は従来の別名表（procedures.yaml）×handles の規則。合わせて一意でなければ「未特定」。**下書きの課は使わない**（作り話かもしれないので、別名表の規則に倒す） |
| 突き合わせ | 当たった語がほかの当たった語（別名表の語も含む）の中にあれば捨てる（「国保」は「国保税」の中）。同じ語で当たったら `when` で絞ったほうを選ぶ |
| 参考資料 | 承認済み（と、設定で使い続ける要再確認）だけ、1 ターン 2 件まで【市の案内（承認済み）】に入れる（持ち物・流れ・期限・金額・問答・職員のメモ。条件つきの持ち物は条件も書く）。番号は参考資料と通し |
| 下書きだけに当たった | 資料に入れず、応答がまだ担当の課を案内していなければ最後に「手続きの詳しいことは、〇〇課でご案内します。」を 1 回（同じ会話の同じ手続きでは繰り返さない）。パック（市のページの写し）は従来どおり使う |
| 期限・金額（WP07） | 承認済みのレコードは参考資料の 1 件なので、`deadline` / `fee` は字面照合の「資料にある」に入る |
| 言い方 | 手続きナレッジと文字 2-gram の重なりが 0.5 以上の最初の文に「市の案内では、」を 1 回だけ添える（課の行は数えない）。手続きナレッジは「〇〇のホームページにも載っています」の一言には数えない |
| 字幕 | 出典に「市の案内（承認済み）「手続き名」」と、`sources` の URL を薄く（エッジの `sources` メッセージに `urls`） |
| 紹介状 | `intake`（最大 3 問）と `bring` は承認済みの手続きナレッジから引く。procedures.yaml からは intake・bring を消した（別名表・asr_exclude・asr_fixes・readings だけ残る） |
| 文字記録 | 応答の行に、当たった手続きの id と状態（`procedures`） |

### 2-2. 下書きの作り方（`scripts/draft_procedures.py`）

```bash
cd server && CUDA_VISIBLE_DEVICES= uv run python ../scripts/draft_procedures.py --site etajima --site akiota --redraft
uv run python ../scripts/draft_procedures.py --site etajima --site akiota --lint   # LLM なしで点検し直すだけ
```

1. パック（江田島 1,175 チャンク・704 ページ、安芸太田 1,652 チャンク・924 ページ）を名前＋探す語で検索し、タイトルに手続きの語があるか、
   本文に 3 回以上あるページだけを最大 3 ページ（郵送・オンラインのページは後ろ）、1 ページ 1,800 字まで材料にする
2. 7560 の Qwen3-8B（temperature 0）に A-1 の形式で JSON を書かせる（資料に無いことは null・空）
3. **機械的に点検して、根拠の無い項目を外す**（外したものは `staff_note` に書く）:
   - 持ち物・流れ・対象・問答の答え: 材料のページと文字 2-gram の重なり（持ち物 0.6・流れ 0.55・ほか 0.4〜0.45）
   - 期限・金額: 加えて、数（単位つき）と支払方法の語がそのまま材料にあり、**手続きの語と同じ行にある**こと
     （戸籍謄本の手数料に、同じ表の別の行の 200 円を書いたため）
   - 郵送・オンラインの申し込みだけの持ち物（郵便小為替・返信用封筒・スマートフォンなど）、過ぎた日付、中国語の漢字（「夫妇」）
4. **担当課は規則だけで決める**（対象一覧の `handles` を facility の handles と、`dept_names` を課名と突き合わせ。複数ならこの建物の課、
   それでも決まらなければ空欄にして職員が付ける）。初回は一意に決まらないものを LLM に選ばせたが、安芸太田の転入届を総務課にするなど
   誤りが多かったのでやめた
5. `sources` に材料に使ったページの URL と確認日、`content_hash` に材料のページの本文ハッシュ（パックの page_hash）。全部 `status: draft`

1 件 6〜10 秒、100 件で約 14 分。

### 2-4. 職員パネル「手続き」タブ（`/staff/procedures/`）

- 職員パネル（`/staff/`）の上に「紹介状・今日の状況 / 手続き」のタブ。要再確認があれば件数を赤で出す
- 一覧: 手続き名・担当課・状態（下書き／承認済み／要再確認）・出典の確認日・想定問答の数。状態で絞り込み（要再確認を先頭に）
- 詳細: 全項目を編集（言い方・絞り込みの語・担当課（拠点の課から選ぶ）・対象・持ち物（「品名 | 語1、語2」で条件つき）・流れ・期限・金額・
  聞き取り・想定問答・職員のメモ）。出典 URL はリンク。下書きの点検のメモを表示。「保存」「内容を確かめたので承認する」（確認のダイアログ）
  「差し戻し（下書きに）」「要再確認を解除」。承認者はログイン名（Basic 認証のユーザー名、既定 staff）と時刻。承認済みを編集すると、
  編集した人が承認したことになる
- 「想定問答を試す」: その手続き**だけを承認済みとみなした**一時の手続きナレッジで、faq の問いを実際の対話（知識パック・人物像あり）に通し、
  答えを並べる。○×を付けると、×は `~/idobata-data/review/procedures_<日付>.jsonl` に素材として書く
- API: `GET /staff/api/procedures[?status=]`、`GET/PUT /staff/api/procedures/{id}`、`POST .../{id}/approve|send_back|clear_recheck`、
  `POST .../{id}/faq/try`、`POST .../{id}/faq/review`（Basic 認証・LAN のみ、既存と同じ）。状態は承認の操作でしか変えられない（編集で
  status を送ると 422）
- 書き込みは YAML を直接（一時ファイルに書いて置き換え）。同時編集は考えない

### 2-7. 人間（Norio）が職員役で 10 件を承認する手順

   （ユーザー staff）
3. 状態で「下書き」に絞る。おすすめの 10 件（材料のページが手続きそのもののページで、中身が比較的そろっているもの・江田島）:
   juminhyo（住民票）、inkan（印鑑登録）、tennyu（転入届）、tenshutsu（転出届）、jido_teate（児童手当）、kodomo_iryo（子ども医療費）、
   passport（パスポート）、koseki_shomei（戸籍謄本）、boshi_techo（母子健康手帳）、kokuho_withdraw（国保の脱退）
4. 1 件ずつ: 出典のリンクを開いて読み比べる → 違う・足りない項目を直す（下の 4 章の誤りの型を見る。迷う項目は消して空にする。
   空欄は「担当の課でご案内します」に倒れるので安全）→ 担当課を確かめる → 「保存」
5. 「想定問答を試す」で答えを見て ○× を付ける（× は素材に残る）。答えがおかしければ問答や項目を直して試し直す
6. 「内容を確かめたので承認する」。承認者は staff と時刻が残る
7. 対話で確かめる: その手続きを聞くと「市の案内では、〜」と答え、字幕に出典の URL が薄く出る。
   取り消すときは「差し戻し（下書きに）」（次のターンから使わなくなる）
