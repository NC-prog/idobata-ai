## 1. A — 手続きナレッジの形式と読み込み

### 1-1. 置き場と形式

- `~/idobata-data/procedures/<site>/<id>.yaml`（1 手続き 1 ファイル、git 管理外。市が育てる成果物）。形式は指示書 A-1 のとおり
  （`id / name / aliases / department / floor / audience / bring / steps / deadline / fee / related / intake / faq / sources /
  status / approved_by / approved_at / staff_note / content_hash`）。足した項目は 3 つ:
  - `when`: 名前・別名に加えて、この語のどれかが発話にあるときだけ当たる（「マイナンバーカード」＋「なくし」で紛失、無ければ申請）
  - `tags`: 紹介状のタグ（`tags.yaml` の統制語彙）
  - `recheck_reason`: 要再確認になった理由
- `bring` は文字列か `{item, when}`（その語が話に出たときだけ紹介状の後に案内する持ち物。WP04 の国保の 2 つの持ち物を移すため）
- コード: `server/src/procedure_kb.py`（読み書き・突き合わせ・承認・再確認）、`server/src/procedures.py`（担当課・聞き取り）

### 1-2. 対話での使い方

| 項目 | 実装 |
|---|---|
| 読み直し | 読むたびにディレクトリのファイルの更新時刻を見て、変わっていれば読み直す（職員パネルの承認・編集が次のターンから効く。再起動不要） |
| 優先順位 | 固定事実（facility、システムプロンプト）＞**承認済み**の手続きナレッジ（【市の案内（承認済み）】、参考資料より前）＞パック＞LLM の一般知識 |
| 担当課 | 承認済みのレコードの `name`（括弧書きを除く）・`aliases` が発話にあればその `department`。残りの発話は従来の別名表（procedures.yaml）×handles の規則（C で、別名表に死亡届・期日前投票・転校・犬の登録・仕事探し・年寄りの相談などを足し、handles を持たない課を名前で引く `departments` と、**候補が複数でこの建物の課が 1 つならその課**を足した）。合わせて一意でなければ「未特定」。**下書きの課は紹介状の課には使わない** |
| 突き合わせ | 当たった語がほかの当たった語（別名表の語も含む）の中にあれば捨てる（「国保」は「国保税」の中）。同じ語で当たったら `when` で絞ったほうを選ぶ |
| 参考資料 | 承認済み（と、設定で使い続ける要再確認）だけ、1 ターン 2 件まで【市の案内（承認済み）】に入れる（持ち物・流れ・期限・金額・問答・職員のメモ。条件つきの持ち物は条件も書く）。番号は参考資料と通し |
| 下書きだけに当たった | 資料に入れず、応答がまだ担当の課を案内していなければ最後に「手続きの詳しいことは、〇〇課でご案内します。」を 1 回（同じ会話の同じ手続きでは繰り返さない）。パック（市のページの写し）は従来どおり使う |
| 期限・金額（WP07） | 承認済みのレコードは参考資料の 1 件なので、`deadline` / `fee` は字面照合の「資料にある」に入る |
| 言い方 | 手続きナレッジと文字 2-gram の重なりが 0.5 以上の最初の文に「市の案内では、」を 1 回だけ添える（課の行は数えない）。手続きナレッジは「〇〇のホームページにも載っています」の一言には数えない |
| 字幕 | 出典に「市の案内（承認済み）「手続き名」」と、`sources` の URL を薄く（エッジの `sources` メッセージに `urls`） |
| 紹介状 | `intake`（最大 3 問）と `bring` は承認済みの手続きナレッジから引く。procedures.yaml からは intake・bring を消した（別名表・asr_exclude・asr_fixes・readings だけ残る） |
| 文字記録 | 応答の行に、当たった手続きの id と状態（`procedures`） |

## 2. B — 初版 50 件の下書きと職員パネル

### 2-1. 対象一覧（`server/context/procedure_catalog.yaml`）

指示書の例を出発点に 50 件（先頭 3 件は移行した承認済み）。名前・別名・`when`・タグ・**担当課を決める語（`handles` / `dept_names`）**・
パックを探す語・網羅試験の言い方 2 つ（丁寧／くだけた・方言気味）を持つ。「〔市町〕」は拠点の 市 / 町 に置き換える。

### 2-2. 下書きの作り方 — Claude Code が出典ページを読んで書く（`scripts/draft_procedures.py --import-dir`）

1. **材料のページを選ぶ**（`--candidates`）: パックの全ページ（江田島 704・安芸太田 924）を、手続き名・別名・探す語がタイトルにいくつあるか
   （1 つ 6 点）、handles の語がタイトルにあるか（3 点）、本文の手続きの語の数（10 点まで）、本文に担当課の名前があるか（2 点）で採点し、
   郵送・オンラインのページ（-2）と抽選・イベント・入札・募集の記事（-5）を下げて、上位 6 ページを候補にする（付録 A に一覧）。
   候補の中から、手続きそのものの窓口のページを Claude Code が読んで選んだ（観光案内に抽選の記事を当てない。候補に良いページが無いときは、
   パックのタイトルの一覧から探した）
2. **書く**: A-1 の形式で、持ち物・流れ・期限・手数料・対象・問答の答えは**ページに書いてある言葉で、書いてあることだけ**。無ければ null／空。
   一般論の作文（「確認の印が押されます」など）は書かない。各項目に根拠の URL（`sources[].items` に、そのページを根拠にした項目名）。
   課の名前がページにあれば `department` に書いてよい（URL つき）。無ければ対象一覧の規則の課（facility の handles）。
   過ぎた日付（令和7年度の募集期間など）は書かず、`staff_note` に残した。書いたファイルは `~/idobata-data/procedures_src/<site>/`（git 管理外）
3. **照合して取り込む**（`--import-dir`。全部 `status: draft`）:
   - 項目の語（漢字・カタカナの 2 字以上）が、根拠のページ（タイトルを含む）に無ければ問題
   - 数（単位つき）がページに無ければ問題。ページの数の前後 40 字に、**項目で数のすぐ近くに書いた語**（「登録手数料」「再交付」など）が
     すべて無ければ問題（数の近くに語が無いときは同じ文の語か手続きの語）。**金額は、手続きの when の語（マイナンバーカードの更新なら
     「更新・期限・切れ・有効期」）も数の前後に要る**（同じページの「マイナンバーカード再交付 1件 800円」を更新の金額にしない。テストあり）
   - 全角数字・桁区切り（15,000）はそろえてから比べる
4. 問題が 0 件になるまで直した（言い回しをページに合わせる、根拠の URL を足す、確かめられない数は空にしてメモに書く）
