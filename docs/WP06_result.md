## 1. 会話の文字記録（指示 1）

### 保存するもの（`server/src/transcripts.py`）

`$DATA/transcripts/<site>/<date>.jsonl` に 1 発話 1 行。音声・映像は残さない。

| 話者 | 項目 |
|---|---|
| 共通 | `ts`（JST、ミリ秒）・`session_id`（会話ごと、12 桁）・`edge_id`・`speaker` |
| `user` | `asr_raw`（ASR の生テキスト）・`text`（聞き取り間違いの対応表を当てた後）・`language`・`ignored`（保存直後の断片など、応答しなかった理由） |
| `backchannel` | `text`（相槌の言葉） |
| `assistant` | `text`（読み上げた文）・`proposal`（このターンで提案した行為／返事をした相手の行為と段／結果 accepted・declined など）・`search_query`（知識パックの検索語。日付を足したもの）・`lookup_query`（調べるの検索語）・`references`（参考資料のチャンク ID・題・URL）・`cited`（応答が出典にした ID）・`dropped`（安全装置で読み上げなかった文と理由）・`timing`（発話終了からの ASR・相槌・1 文目・音声開始・LLM 完了の秒と検索 ms）・`trigger`（電話番号の聞き直しなど、発話に依らない応答） |

- **紹介状の聞き取りで伺った氏名・地区・電話番号は書かない**（`（お名前を伺いました）` に置き換える。画面・コンソールと同じ扱い。
  紹介状 JSON だけに残る）。保存直後に無視した断片は数字を `＊` に伏せる
- 応答の文は画面と同じく、聞き取った値を `＊＊` に伏せたもの
- 保持は `IDOBATA_TRANSCRIPT_RETENTION_DAYS`（既定 7）。起動時に、今日から 7 日より前の日のファイルを消す
- **保全**: セッション単位で `holds.json` に印を付けると、期限を過ぎてもその会話の行だけ残す（外すと次の起動で消える）

### 管理者ページ（`/admin/transcripts/`）

- 職員パネルとは別のロール: ユーザー `admin`、パスワード `IDOBATA_ADMIN_PASSWORD`（空なら 503）。職員パネルと同じく LAN 内からだけ（外は 403）。
  職員の資格では読めない（401）、管理者の資格では職員パネルを開けない（401）
- 日付を選ぶ → セッションの一覧（時刻・発話数・保全中）→ 1 セッションの記録（ASR の生テキストが違えば併記、捨てた文は赤字、
  提案・検索語・出典・計測は JSON で）。「保全する／保全を外す」ボタン
- API: `GET /admin/api/transcripts/days`・`GET /admin/api/transcripts?day=`・`GET /admin/api/transcripts/{day}/{session}`・
  `POST /admin/api/transcripts/{session}/hold {"held": true}`
- `IDOBATA_ADMIN_PASSWORD` だけを入れても HTTP サーバ（8080）が立つ

## 2. 誤り探しの素材（指示 2、`scripts/export_review.py`）

```
uv run --project server python scripts/export_review.py [--site etajima] [--date 2026-10-22] [--data-dir …]
```

`$DATA/review/<date>.jsonl` に 1 件 1 行（同じ日を流し直すと上書き）。

| kind | 抜き出すもの |
|---|---|
| `asr_fixed` | 対応表で直った発話（`asr_raw` と `text`） |
| `dropped` | 安全装置で読み上げなかった文（理由と、直前の来訪者の発話） |
| `declined` | 提案が辞退された往復（提案した往復と、辞退の返事の往復） |
| `rephrased` | 来訪者が言い直した往復（直前の来訪者の発話と文字 2-gram の重なり 0.5 以上、5 字以上） |

- 伏せるもの: 電話番号らしい数字の並び（漢数字・「ゼロ」も）、「私は〇〇です」「名前は〇〇です」「〇〇さん」の名前、番地・丁目、
  拠点 YAML の地名（`place_names` と `offices` の「〜町」。市の名前そのものは伏せない）
- 紹介状の聞き取りの置き換え（`（お名前を伺いました）`）が続くのは言い直しにしない（確認の途中で、置き換えどうしが言い直しと判定されたため直した）
- エッジの確認の記録から作ると、`dropped` 1 件（提案文の前の問い「最近、お変わりありませんか？」）だった

## 3. アバターの呼び名（指示 3）

- `IDOBATA_AVATAR_NAME`（既定 いどちゃん）を ASR の静的語彙の**先頭**に置く（手続きの語より前）
- VOICEVOX のユーザー辞書に入れる。ひらがな・カタカナだけの名前ならカタカナの読み（イドチャン）を付ける。アクセント核は
  `actions.avatar_accent`（1、イ\ドチャン）。漢字の名前なら ASR の語彙だけ
- `procedures.yaml` の聞き取り間違いの対応表に `伊豆ちゃん → いどちゃん` を入れた

## 4. 紹介状の要約の窓・タグ・案内役のメモ（指示 4）

- 要約に渡す範囲を「提案 refer のきっかけになった発話」＋同意・聞き取りの答え（全部）にした。きっかけより前の往復は使わない。
  これで要らなくなった「話題の始まり」の追跡（`topic_floor`・`window_turns`）は消した
- `procedures.yaml` の手続きに `tags` を足した（国保・後期高齢 → 保険・年金、国保税・税証明 → 税、介護保険 → 介護、児童手当・保育 → 子育て、
  住民票・住民登録・戸籍・印鑑 → 住民票・戸籍、マイナンバーカード → マイナンバー、ごみ → ごみ。パスポート・水道は合う語彙が無いので付けない）。
  手続きが分かれば、そのタグを先に、LLM の選んだタグを後ろに足す（最大 5、統制語彙に無いものは捨てる）
- 要約と案内役のメモは、来訪者の言葉・案内役の言葉に聞き取り間違いの対応表を当ててから作り、出力にも当てる（「国宝」を職員に渡さない）

## 5. 館内の設備の作り話（指示 5）

`dialogue.building_claim_patterns`（3 つ）で、館内の話（ロビー・〜階・庁舎・ここに など）をしている文の「〜があります」「〜にあります」の名詞を取り出し、
`facility.facilities_in_building`・`departments`・施設名のどれにも当たらなければ読み上げない。

| 文 | 結果 |
|---|---|
| ロビーにはお茶コーナーがあります | 捨てる（WP05 の雑談 s8） |
| 2階には相談室があります／受付は1階ロビーにあります／ここには休憩スペースがあります | 捨てる |
| 保健医療課は2階にあります／1階ロビーに市民課の窓口があります／AEDは1階ロビーにあります | 読む（登録あり） |
| 公民館で料理教室があります | 読む（館内の話ではない） |

トイレなど場所を聞かれやすい設備は、これまでどおり先に「近くの職員にお尋ねください」へ差し替える。

## 6. 雑談寄りの発話の参考資料（指示 6）

挨拶・天気・人物像への質問（`dialogue.smalltalk_pattern`）では、参考資料のベクトル類似度のしきい値を 0.88 に上げる
（`dialogue.smalltalk_min_vector_score`）。実測（知識パック etajima）:

| 発話 | 付いていた資料（類似度） |
|---|---|
| 日本語うまいですね | やさしい日本語での「外国人市民のため…」（0.837）、窓口案内指さしシート（0.801） |
| こんにちは。ちょっと寄ってみました… | 栗原恵の愛おしい時間（0.810） |
| 最近、急に寒くなりましたね… | 熱中症にご注意ください（0.833） |
| あなたは職員さんですか | ボランティアに関すること（0.800） |
| （参考）住民票の写しを取りたい／大雨のときの避難所／国保の切り替え | 0.82〜0.89（雑談の型に当たらないので、しきい値はふだんのまま） |

雑談の誤った資料はどれも 0.80〜0.84 で、BM25 の語の一致（「日本語」）の例外で入っていた。評価セット 22「日本語お上手ですね」の参考資料は「なし」になった。

## 7. 電話番号の聞き直しの間（指示 7）

続きを待つ期限を過ぎても、VAD が発話区間の途中か、その区間を ASR に掛けている途中か、応答のタスクが残っていれば、終わるまで待ってから
「もう一度、ゆっくりお願いします」を言う（`VoiceLoop._hearing`）。待っている間に続きの断片が来れば期限が延び、聞き直さない。

### `--mode voice --edge` で国保の流れ（コミット 3702416）

エッジは Playwright のヘッドレス Chromium。`getUserMedia` を差し替えて、ページの AudioContext から WAV を「マイク」として流した。
国保の相談 → お願いします → 聞き取り 3 問 → 名前 → はい → 地区 → 電話でお願いします →
**電話番号の 3 断片（「ゼロキューゼロの。」「イチニーサンヨンの。」「ゴーロクナナハチ。」を間をあけて 1 つの音声で）** →
**「はい」の直後に「ゴーロクナナハチ」が重なる** → 読み上げが終わってから「はい」。

```
[聞き取り:ja] お電話番号：伺いました
INFO: 電話番号の続きを待ちます（いま 3 桁、6 秒）
[聞き取り:ja] お電話番号：伺いました
INFO: 電話番号の続きを待ちます（いま 7 桁、6 秒）
[聞き取り:ja] お電話番号：伺いました
INFO: 電話番号の数字がそろったので復唱します
[井戸端AI] お電話番号は、＊＊、でよろしいですか？
[聞き取り:ja] お電話番号：伺いました
INFO: 紹介状の保存直後の短い断片を無視しました          ← 保存の途中に聞き取った「五六七八」
INFO: 紹介状を保存しました: 受付 3384・保健医療課・聞き取り 3 問
[井戸端AI] 保健医療課に伝えておきました。受付番号は、3384番です。…
[聞き取り:ja] はい。
[井戸端AI] はい。ほかにも何かあれば、お気軽にどうぞ。     ← 名前・番号を聞き返さない
```

- 紹介状: 保健医療課・電話・`090-1234-5678`・タグ `保険・年金`（手続きから）＋`住まい`（LLM）。
  **要約は国保の話だけ**: 「国保の切り替えについて相談しており、来月から会社を退職したため、手続きが必要であると説明しました。」
- 文字記録: 1 セッション 28 行。氏名・地区・電話番号は入っていない（聞き取りの答えは置き換え、保存直後の断片は `＊＊＊＊。`）

### 確認の途中で見つけて直したもの

- **保存の途中に聞き取った断片が LLM に渡った**（コミット 1bdfb95）: 「はい」の直後の「五六七八」は、紹介状の要約を作っている間に聞き取られ、
  受付番号の読み上げ（約 12 秒）が終わるまで順番を待つ。順番が来た時には保存から 10 秒を過ぎていて、無視されずに LLM が答えた。
  画面とコンソールにも番号の断片が出ていた。保存の途中は断片を無視し、10 秒は「聞いた時刻」から数えるようにした
- **定型文で答えたターンに、前の LLM のターンの検索語・出典・捨てた文が残っていた**（コミット 3702416）: 文字記録・計測（検索 ms）・
  エッジの出典表示に前のものが出ていた。ターンの始めに消すようにした
- エッジの確認で、Chromium の音声出力が既定の出力機器（この時は USB の Avaya B109）で止まり、AudioContext ごと進まなくなった
  （1.5 秒で 0.01 秒しか進まない）。確認用のブラウザは `--disable-audio-output` で動かした（部屋に音も出ない）

## 9. 気づいたこと・残り

- 要約の言い回しは LLM 任せで、「来月から会社を退職した」「〜と説明しました」のように順番や主語がずれることがある（中身は国保の話だけ）
- 手続きのタグの後ろに足す LLM のタグに、合わないもの（今回は「住まい」）が入る。手続きが分かったときは LLM のタグを使わない、も選べる
- 文字記録には、ふだんの会話の中で来訪者が自分から言った名前・番号は残る（掲示で知らせる前提。誤り探しの素材では伏せる）
- 評価セット 3 の「お住まいの近くにどの窓口が…？」は、個人情報を尋ねる文の型（「お住まいは」「お住まいを」）に当たらない。型を広げるかは要検討
