# WP12 結果 — 会話音声の保存（7 日）と管理者ページでの再生

対象機: 7560（standalone）。ブランチ `feature/wp12-audio`。指示書は `docs/WP12_audio_retention.md`。

**ブランチの起点**: 指示書は「WP11 のマージ後に main から切る」だが、2026-10-24 の時点で main は 34921f6（WP10 のマージ）のままで、
WP12 の指示書も WP11 の後始末に要るコードも `feature/wp11-news` にしか無かったので、`feature/wp11-news` の先頭（9953264）から切った。
WP11 を main にマージした後なら、そのまま main の上に乗る。

止まる条件の確認:
- VAD の出口: マイク・エッジ（ブラウザの PCM）・WAV 入力のどれも `main.py` の `_run_pipeline` を通る（1 か所）。保存はその先の `_on_segment`（と短すぎた区間の `_on_short_segment`）に置いた
- 文字記録の行の id: これまで無かった。新しい行に `id` を足し、古い行（WP06〜WP11 の形）は id・audio が無いだけで、そのまま読める（管理者ページでは「音声なし」）
- 書き込みの遅れ: 書き込みは別スレッド。ターンの側でかかるのは頼むだけで、単体テストで 10 秒の区間でも 50ms 未満（`test_keep_audio_does_not_block_the_turn`）

## A. 保存

- `AudioRetentionConfig`（`config.audio`）: `retention_days=7`（`IDOBATA_AUDIO_RETENTION_DAYS`、0 で保存しない）、`sample_rate=16000`、`format="wav"`、
  `include_intake=True`、`min_free_bytes=1GB`、`subdir="audio"`。`.env.example` に 1 行足した
- 置き場: `~/idobata-data/transcripts/<site>/<date>/audio/<id>.wav`（16kHz モノラル 16bit、ASR に渡したのと同じ波形＝前後のマージンと短い返事の無音の足しを含む）。
  `transcripts.AudioStore` が書く・配る・掃除する
- 文字記録の来訪者の行に `id`（`HHMMSS-xxxxxx`。音声のファイル名と同じ）・`asr_status`（ok / empty / other_language / rejected_short / no_party）・
  `audio`（`<date>/audio/<id>.wav`。音声を残したときだけ）を足した
- 聞き取れなかった区間（ASR が空）・短すぎて ASR に渡さなかった区間も、輪があれば音声と行を残す（文字は空、`ignored` に理由）。
  輪が無くて ASR に渡さなかった区間は残さない（行も書かない。従来どおり）。輪の外の話者と分かった区間は、行（no_party）だけ書いて音声は消す
- 紹介状の聞き取りの区間も残す（`include_intake`）。文字記録は従来どおり「（お名前を伺いました）」
- 書き込みは別スレッド（`asyncio.to_thread`）。終了時は書きかけを 5 秒まで待つ。空きが 1GB を切ったら保存を止めて WARNING を 1 回
- 掃除: 起動時に加えて、**毎日 4 時（`TranscriptConfig.cleanup_hour`）の掃除**をアプリ内のタイマーで足した。紹介状・来訪記録・小ネタ・文字記録・音声を
  同じ掃除で消す（`VoiceLoop.cleanup_stores`）。音声は文字記録より先に見る（保全の判定に行の id を使う）。保全したセッションの音声は残す。
  保存日数を 0 にしたら、残っている音声もすべて消す
- `scripts/export_review.py`: 音声は入れない。来訪者の行に `utterance_id` を付け、聞き取れなかった区間を `unheard` として足した。
  `--with-audio` のときだけ、素材に出てきた発話の音声を `review/<date>_audio/` に並べて出す（既定オフ）
- 「録音してる？」の答え（`privacy_lines`）も掲示文言の案に合わせた（「お話は、文字と声の記録を 7 日間、庁内に残し、品質の確認のために決まった管理者だけが
  確かめて、その後消します。声や映像が建物の外に出ることはありません。…」）。音声を残さない設定では WP06 の文言（「声は録音していません」）

## B. 管理者ページ（`/admin/transcripts/`）

- 来訪者の行に ▶（HTML5 audio）。音声は `/admin/transcripts/audio/<date>/<id>`（Basic 認証・LAN のみ・Range 対応・`Cache-Control: no-store`）。
  日付と id の形を確かめ、ほかのファイルは配らない
- `asr_status` が ok 以外の行に赤い印（聞き取れず・他の言語・短すぎ・輪の外）
- セッションの画面に「このセッションの来訪者の音声を順に再生（N 件）」と「止める」。再生中の行を黄色で強調
- 保全はセッション単位で音声にも効く（既存の holds.json）
- セッションの一覧に「音声」列（あり／なし）、日付の横にその日の音声の件数と合計サイズ

## C. 確認

- 単体テスト（`tests/test_wp12_unit.py`、11 件）: 16kHz モノラル 16bit で書く・パス・形の違う日付と id は配らない、保存日数 0 で何もしない、
  空きが足りないと止めて WARNING は 1 回、期限切れは消え保全したものは残る・外すと次の掃除で消え空のディレクトリも消える、
  管理者の配信（認証なしは 401・200・Range で 206・no-store・無い id は 404）・一覧の「音声」列・合計サイズ、
  パイプラインで ok の行と音声・聞き取れなかった区間と短すぎた区間は残し輪が無いときは残さない・保存日数 0 では行だけ、
  頼むだけなら 50ms 未満、素材への書き出しは `--with-audio` のときだけ、「録音してる？」の答えが設定に従う
- 既存のテストのうち `VoiceLoop` を作るもの（`test_main_unit` / `test_camera_unit`）が、文字記録だけ作業用のディレクトリに差し替えていて、
  音声が本物の置き場を向いたままだった。最初の実行で試験用の合成波形が `~/idobata-data/transcripts/etajima/2026-10-24/audio/` に 6 件書かれたので、
  消して、テストの組み立てで音声も作業用のディレクトリに向けた
- `--input-wav tests/fixtures/visitor_procedure_ja.wav`（作業用のデータディレクトリ）で 1 往復: `2026-10-24/audio/154859-efc427.wav`（157,740 バイト、約 4.9 秒）ができ、
  文字記録の行（`id: 154859-efc427`、`asr_status: ok`、`audio`）から辿れた。続けて管理者ページを立てて curl:
  認証なし 401、`Range: bytes=0-1023` で **206 Partial Content**・`content-range: bytes 0-1023/157740`・`cache-control: no-store`・`audio/wav`。
  セッション一覧の「音声あり」、その日の合計（1 件・157,740 バイト）、ページの「来訪者の発話の音声は 7 日」
- 紹介状の聞き取りを含む会話（来訪者役の 9 発話を VOICEVOX で合成して流した）: 聞き取りの区間（お名前 5・お住まい 1・ご連絡方法 1）も音声が残り、
  文字記録の行は「（お名前を伺いました）」などに伏せられていた。お名前を言った区間の音声を ASR に掛け直し、名前が入っていることを確かめた（中身はここに書かない）。
  （この会話では ASR が「国保」を「国庫法」と聞き、手続きの聞き取りは無く共通の項目だけになった）
- ディスクの見積もり: 1 発話 5 秒 ≈ 160KB（実測 4.9 秒で 157,740 バイト）。1 日 200 発話で約 32MB、7 日で約 230MB。空きが 1GB を切ったら保存を止める
- 確認で起動したプロセスはすべて止めた（実機確認のプロセスが 8080 / 8765 を使っていたので、確認は 18080 / 18765・28080 / 28765 で動かした）
