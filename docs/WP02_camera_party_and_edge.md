# WP02 — カメラ・「輪」・能動的な切り出し・別機エッジ（Claude Code 向け作業指示）

対象機: 7560（standalone、WP06 完了。main 38cc4df）
カメラ: Logitech HD Webcam C525（USB、720p、画角約 69°、`/dev/video4`）。内蔵カメラは使わない。設置時は画角 78〜90° のものに替える前提で、画角に依存する値は設定に出す。
目的: いどちゃんが「聞かれたら答える」から「目の前の人に気づいて、声をかけ、その輪の中の人とだけ話す」に変わる。あわせて、別機の Windows エッジ PC に置ける形にする。

前提の決定（2026-10-21〜22、構想メモ「会話の相手は『輪』で決める」）:
- 会話の相手は 1 人に絞らず **1:N**。N は「目の前の輪（party）」＝画面手前の一定距離・正面寄りにいる 1〜3 人。
- 声の割り当てはセッション限りの話者区別（埋め込みは会話が切れたら破棄。登録・照合はしない）。輪に人がいるときに現れた話者クラスタだけを相手として受け付ける。
- 映像フレームは保存しない。顔識別（個人特定）はしない。
- 受け身にしない：目が合ったら切り出す。黙っていれば一言。「お困りのことは」の類は 1 会話 1 回。

WP02 は **A → B → C → D** の順。A・B を終えて push してから C。D は設計書と手順書が中心（別機が手元にあれば実測まで）。

---

## A. カメラと「輪」（camera_client）

### A-1. 映像の経路

- エッジ（ブラウザ）が `getUserMedia({video:{width:640,height:360,frameRate:10}})` でカメラを取り、**320×180 の JPEG を 5fps** で WebSocket のバイナリフレーム（既存の音声と同じ接続、種別バイトで区別）としてフロントへ送る。標準化のため、カメラを Python から直接開く経路は作らない（別機エッジでも同じ形で動かすため）。
- フロントは受け取ったフレームを **メモリ上でだけ**処理し、ディスクに書かない。デバッグ用に `--camera-debug` を付けたときだけ、検出結果の矩形とキーポイントを重ねた画像を `/edge/debug` に配信（ブラウザで見る。保存はしない）。

### A-2. 検出（YOLO11-pose）

- `ultralytics` の `yolo11n-pose`（GPU、予備枠の中。VRAM 使用量を実測して結果文書に書く。1GB を超えるなら `imgsz` を下げる）。人物の矩形と 17 キーポイント。
- **輪の判定**（毎フレーム、人ごと）:
  - 距離：矩形の高さが画面高さの `party.min_box_ratio`（既定 0.35。C525 で 2.5m 相当。設定）以上。
  - 正面：鼻・両目が見えており、左右の耳（または目）の x 座標の中点が鼻の x から画面幅の `party.face_center_tol`（既定 0.04）以内 → 正面寄り。
  - 滞留：上の 2 条件が `party.dwell_sec`（既定 2.0）続いたら「輪の中」。外れて `party.leave_sec`（既定 3.0）経ったら「輪の外」。
  - 輪は最大 3 人。人の対応付けは `ultralytics` の ByteTrack のトラック ID（セッション限り、保存しない）。
- 状態：`NONE`（誰もいない）→ `PRESENT`（距離条件のみ）→ `PARTY`（輪に 1 人以上）。エッジへ `{type:"party", count, facing:true/false}` を送り、アバターの視線・姿勢に使う（PRESENT で顔を上げる、PARTY で相手を見る）。
- `IDOBATA_CAMERA=0` ならカメラ無しで従来どおり（常に PARTY 扱い）。

### A-3. 聞く・聞かないの制御

- `NONE`／`PRESENT` の間は **ASR に渡さない**（VAD は回すが結果を捨てる。後ろの会話や職員の声を拾わない）。`PARTY` のときだけ対話に流す。
- 輪が `NONE` になって `party.bye_sec`（既定 8 秒）経ったら会話を区切る（既存の待機タイムアウト 90 秒より先に効く）。別れの一言（「お気をつけて」「またどうぞ」）は輪が解けた直後に 1 回だけ。

### A-4. 完了条件（A）

- `--camera-debug` で、1 人がカメラの前に立って正面を向くと 2 秒で `PARTY` になり、横を向いて 3 秒で外れること。2 人並ぶと count=2。
- 輪が無いときに部屋の会話（WAV をスピーカーから流す）を拾わないこと。
- VRAM の実測（YOLO 込みで 16GB に収まる）。推論の 1 フレーム時間（目標 20ms 以下）。
- pytest / mypy / ruff。`feature/wp02-camera-party` に push。

## B. 話者の区別（session-scoped speaker clustering）

- 発話区間ごとに話者埋め込みを取る。モデルは CPU で 50ms 以内のもの（候補：`speechbrain` の ECAPA-TDNN、`wespeaker` の小型モデル、`pyannote` の埋め込み。**ライセンスを確認して選び、結果文書に書く**。重みの配布元・条項を転記）。
- セッション内で埋め込みをオンラインクラスタリング（コサイン類似度、しきい値は実測）。クラスタは `A`, `B`, `C`… と番号だけ。
- **受け付け規則**：そのクラスタが最初に現れた時刻に輪が `PARTY` だったら「相手」。輪が `NONE`／`PRESENT` のときにしか現れないクラスタは捨てる（A-3 の制御と二重の網）。
- LLM に渡す発話は `A：〜` `B：〜` のラベル付き。紹介状の聞き取りは、同意を言った話者のラベルを主とし、他の話者の答えも受け付ける（付き添いが代わりに答える）。来訪記録に話者数を足す。
- 会話が区切られたら埋め込みとクラスタを破棄（メモリのみ。ディスクに書かない）。
- 完了条件：VOICEVOX の 2 話者で「本人」「付き添い」の会話 WAV を交互に流し、ラベルが安定して付くこと。輪が無いときに流した第三の話者が捨てられること。

## C. 能動的な切り出しと沈黙

- **切り出し**：`PARTY` になった瞬間、時間帯の挨拶＋季節・天気の一言＋開いた問いを 1 つ（`server/context/openers.yaml`。例：「こんにちは。今日は風が冷たいですね。お元気にされてました？」）。問いは「お元気」「何かお困り」「どちらまで」のような開いたものから、1 会話 1 回。天気の一言は `weather.json` から。
- 切り出しは LLM を通さず定型（遅延ゼロ、事前合成）。2 回目以降の同じ輪には言わない。
- **沈黙**：`PARTY` のまま相手が `party.silence_sec`（既定 7 秒）黙ったら、「ゆっくりで大丈夫ですよ」「ほかにも何かあれば」のどれかを 1 回。沈黙の一言は 1 会話 2 回まで。
- **別れ**：A-3 のとおり。
- 評価：3 人（本人役の WAV＋カメラ前の人）で、切り出し→会話→沈黙→別れの流れをログで確認。切り出しの開始が `PARTY` から 0.5 秒以内。

## D. 別機エッジ（Windows ミニ PC）の設置設計

- **設計書 `docs/edge_pc_setup.md`**：
  - 構成：エッジ PC（Windows 11、内蔵 GPU）＋ USB カメラ（画角 78〜90°）＋ AEC 付き USB スピーカーフォン＋縦置きモニタ。フロント AI 機とはスイッチングハブで直結。
  - ブラウザのカメラ・マイク取得は secure context が必要。**方式を決めて書く**：①エッジ PC で小さなローカル配信（`http://localhost:8080/edge/` を reverse proxy か静的配信で出し、WebSocket だけフロントへ）、②Chrome のキオスク起動に `--unsafely-treat-insecure-origin-as-secure=http://<front>:8080` を付ける、③自己署名証明書。推奨は ②（設定 1 行、証明書管理なし）。理由と手順を書く。
  - キオスク起動のショートカット（`--kiosk --autoplay-policy=no-user-gesture-required --use-fake-ui-for-media-stream` 等。`--use-fake-ui-for-media-stream` はマイク・カメラの許可ダイアログを省く）。スリープ無効、自動ログオン、Windows Update の再起動時刻、電源復帰時の自動起動。
  - フロント側は `IDOBATA_EDGE_HTTP_HOST=0.0.0.0` と、エッジ PC の IP だけを許可する設定（`IDOBATA_EDGE_ALLOW`）。
- **手順書**：エッジ PC を箱から出して 30 分で立ち上げる手順。
- 手元に Windows 機（ノート）があれば、同じ LAN からフロント（7560）に接続して 1 往復を実測し、結果文書に書く。無ければ設計書まで。

## 止まって報告すべきこと

- `yolo11n-pose` が予備枠に収まらない（実測を書く。`imgsz` 320 でも超えるなら止まる）。
- 話者埋め込みのモデルで、ライセンスが商用・公共利用に明確なものが見つからない。
- ブラウザからの映像送出で CPU が逼迫し、音声開始が 1.3 秒を超える（フレームレート・解像度を下げた結果も書く）。
