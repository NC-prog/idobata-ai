## A. カメラと「輪」

### 作ったもの

- **エッジ**（`edge/src/camera.ts`）: フロントから hello の後に届く `camera` メッセージの設定で、`getUserMedia({video:{640×360, 10fps}})` を開く。
  複数のカメラがあれば label に「Integrated」（`IDOBATA_CAMERA_LABEL`）を含むものを選ぶ。320×180 の JPEG（品質 0.7）を 5fps で送る。
  開けたかどうかを `camera_status` で知らせる
- **上りのバイナリに種別の 1 バイト**を付けた（`0x01` PCM、`0x02` JPEG。同じ WebSocket）。WP01 の契約からの変更
- **フロント**（`server/src/camera.py`）: 最新の 1 枚だけをメモリに持ち、YOLO11-pose（imgsz 320、FP16、ByteTrack）に掛けて輪を決める
  （`PartyTracker`。推論と切り離した規則だけなのでテストしやすい）。状態が変わったらエッジへ `{type:"party", state, count, facing}`
- **聞く・聞かない**: 発話区間の始まりか終わりに輪（PARTY）があるときだけ ASR に渡す。NONE／PRESENT の間は VAD は回すが結果を捨てる
- **別れと区切り**: 輪が NONE になった直後に「お気をつけて。またどうぞ。」を 1 会話 1 回（会話が始まっていたときだけ。
  `context/openers.yaml`）。NONE が `party.bye_sec`（8 秒）続いたら会話を区切る（来訪記録・話者の区別も消す）
- **アバター**: NONE は少しうつむいて視線を外す、PRESENT で顔を上げる、PARTY で相手（カメラ）を見る（待機・傾聴のときだけ上乗せ）
- **耳を塞がない安全装置**: フレームが `camera.stale_sec`（5 秒）届かなければ輪の判定をやめ、従来どおり聞く。
  `IDOBATA_CAMERA=0` ならカメラ無し（常に PARTY 扱い）
- **`--camera-debug`**: `/edge/debug` に、検出の矩形とキーポイントを重ねた最新の 1 枚（メモリのみ・LAN 内からだけ）と、
  `/edge/debug/party` に状態・人ごとの矩形の高さの割合・推論時間を出す

### 輪の判定（既定値）

| 設定 | 値 | 意味 |
|---|---|---|
| `party.min_box_ratio` | 0.35 | 矩形の高さ／画面の高さ。これ以上なら「近い」 |
| `party.face_center_tol` | 0.04 | 鼻と、左右の耳（片方でも見えなければ目）の中点の横のずれ／画面幅 |
| `camera.kpt_conf` | 0.5 | 鼻・両目が「見えている」とみなすキーポイントの信頼度 |
| `party.dwell_sec` / `leave_sec` | 2.0 / 3.0 | 輪に入る・外れるまでの秒数（見えなくなった人も 3 秒は輪に残す。トラックの切れ目で輪が揺れない） |
| `party.max_members` | 3 | |

**`min_box_ratio` の距離の校正はまだ**（人が 2〜2.5m に立って `/edge/debug/party` の `people` の値を見る必要がある）。
本物のカメラの前にいた人（距離は不明）は 0.35 を超えていた。

### 確認

**本物のカメラ**（`/dev/video0`、ヘッドレス Chromium。マイクだけ差し込み）:

- ブラウザが選んだカメラ: `Integrated Webcam`（640×360）
- カメラの前に人がいた（確認時に席にいた方）: `NONE → PRESENT`（14:29:31）→ **2.0 秒で `PARTY`**（14:29:33）、
  顔をそらして `PARTY → PRESENT`、正面に戻って再び `PARTY`
- **VRAM**: フロントのプロセス 294 MiB（CUDA の文脈込み。YOLO の割り当ては 45 MiB。予備枠 約 3.2GB に収まる。`imgsz` を下げる必要なし）
- **推論**: 中央値 **7.5ms**、95% 7.9ms（目標 20ms 以下）。受信 5.0fps
- 最初の測定では受信が 0.7fps しか出なかった。原因はヘッドレス Chromium の WebGL がソフトウェア描画（SwiftShader）で、
  VRM の描画がメインスレッドを埋めていたこと（50ms のタイマーが 2 秒で 11 回、`toBlob` 1.37 秒）。`--use-angle=gl` で
  Intel UHD（7560 の内蔵 GPU）を使わせると、タイマー 40/40 回、`toBlob` 8.6ms、描画 61fps、受信 5.0fps。
  **エッジのブラウザは GPU で描画させること**（D の設計書に書く）

**作った映像**（canvas の映像をカメラとして差し込み。人の写真は ultralytics に同梱の `zidane.jpg`・`bus.jpg`）＋差し込んだ音声:

| 確かめたこと | 結果 |
|---|---|
| 誰もいないときに部屋の会話（来訪者役の WAV）を流す | `輪が無いので、この発話区間は聞き取りません（NONE）`。ASR に渡さず、字幕も応答も無し |
| 人が来る（`zidane.jpg`） | **2.55 秒で PARTY**（滞留 2 秒＋フレーム間隔と処理） |
| 輪の中で話す | 聞き取り・応答あり。音声開始 **0.32 秒**（相槌）、LLM の 1 文目 0.66 秒（カメラを動かしたままで 1.3 秒未満） |
| 立ち去る（黒い画面） | 3.1 秒で NONE → 別れの一言 → **8 秒で会話を区切る**（`輪が無くなって 8 秒経ったため会話を区切りました`） |
| 2 人並ぶ（`bus.jpg`） | **count=2**（`zidane.jpg` は 2 人写っているが、片方の左目の信頼度が 0.45 で「正面」の条件に届かず count=1） |

**人が横を向いて 3 秒で外れること**は、本物のカメラの前の人で `PARTY → PRESENT` を確かめた（顔をそらした時刻の正確な記録は無い）のと、
ユニットテスト（横向き→ 3 秒で外れる）で確かめた。**部屋の会話をスピーカーから流す確認**は、音を出さず、
同じ音声をブラウザのマイクに差し込んで行った（輪の判定で捨てることの確認としては同じ。マイクとスピーカーの音響の経路は見ていない）。

## B. 話者の区別

### 作ったもの（`server/src/speaker.py`）

- 発話区間ごとに ECAPA-TDNN の埋め込み（192 次元）を取り、会話の中だけでオンラインにまとめる（重心とのコサイン類似度 ≥ 0.45 なら同じ人）。
  話者は `A`・`B`・`C`… の記号だけ。**埋め込みとまとまりはメモリだけ**。会話が区切れたら捨てる（待機タイムアウト・輪が解けて 8 秒・終了時）
- 声の長さが 1 秒未満の区間（「はい」）は埋め込みが不安定なので、新しい話者を作らず近い話者に寄せ、重心も動かさない
- **受け付けの規則**: 最初に現れたときに輪が PARTY → 相手、**NONE → 捨てる**（その後に輪の中で話しても捨てる）。
  **PRESENT（近づいてくる途中）→ 保留**、輪ができてから話せば相手（作業指示の「最初に現れた時刻に PARTY だったら相手」を少し緩めた。
  話しかけながら近づいてくる人を、その会話の間ずっと聞かないことにしないため）
- LLM には `A：〜` `B：〜` の形で渡す（履歴も同じ形）。システムプロンプトに「記号は名前ではない。応答に書かない」を足し、
  応答の頭に `A：` を付けてきたら外す
- 紹介状の聞き取り: 同意を言った人を主とし、別の人の答えも受け付けて、答えの後ろに「（付き添いの方の答え）」と付ける（職員に分かるように）
- 来訪記録に `speakers`（相手として受け付けた話者の数）を足した。文字記録の来訪者の行に `speaker_label`
- 埋め込みは ASR と並べて取る（応答の遅れにしない）

### モデルの速さ（2 秒の区間）

| 動かす場所 | 時間 | |
|---|---|---|
| CPU 4 スレッド | 中央値 116ms（負荷の高いときの別の測定で 102ms） | **目標の 50ms に届かない** |
| CPU 8 スレッド | 78ms | 届かない |
| **GPU（予備枠）** | **4ms**、割り当ての最大 119 MiB | これを既定にした（`speaker.device`、GPU が無ければ CPU） |

作業指示は「CPU で 50ms 以内のもの」だったが、候補（ECAPA は 3 つの中で最も小さい）で CPU 50ms 以内のものが無かった。
GPU の予備枠に約 120 MiB を足しても YOLO と合わせて 1GB に届かない。ASR と並べて動かすので、CPU でも応答は遅れない（`speaker.device: cpu` で切替）。

### しきい値（VOICEVOX の話者で実測）

1 秒以上の区間どうしのコサイン類似度: 同じ人 最小 0.37・中央値 0.64、別の人 95% 0.56・中央値 0.17。
本人と付き添いが交互に 12 回話す並びを、実際のまとめ方に通した結果:

| 組 | 0.40 | **0.45** | 0.50 | 0.55 |
|---|---|---|---|---|
| 玄野武宏（男）／冥鳴ひまり（女） | 12/12 | **12/12** | 12/12 | 11/12（3 人に割れる） |
| 玄野武宏（男）／青山龍星（男） | 12/12 | **12/12** | 11/12 | 10/12 |
| 春日部つむぎ／ずんだもん（どちらも高い女声） | 0/12 | 0/12 | 0/12 | 9/12（4 人に割れる） |

**0.45** にした。VOICEVOX の似た声どうし（つむぎ／ずんだもん、類似度が最大 0.71）は分けられない。人の声での確認はまだ。

### 確認（`--edge`、作った映像＋差し込んだ音声）

誰もいないときに職員役（青山龍星）の声 → 人が来て PARTY → 本人（玄野武宏）と付き添い（冥鳴ひまり）が交互に 3 回ずつ → 会話の途中で職員役がもう一度:

```
輪が無いので、この発話区間は聞き取りません（NONE）     ← 職員の声。話者 A（輪の外）として覚える
新しい話者 B（相手、最も近い話者との類似度 0.28）       ← 本人
新しい話者 C（相手、最も近い話者との類似度 0.16）       ← 付き添い
（文字記録の話者）B C B C B C
輪の外で先に聞いた話者 A の発話なので、応答しません     ← 会話の途中の職員の声
```

ラベルは 6 回とも安定し、職員の声は 2 回とも捨てられた（1 回目は輪が無いので ASR にも渡さず、2 回目は話者で捨てた）。
