## A. 区画の用途（use）

- 区画（seed）に `use: dialogue | lookup | exclude` と `why`、区画と拠点に URL の `use_rules`（`pattern`・`use`・`why`・`final`）。全拠点の題名の規則は `kb/scope_rules.yaml`
- 決め方の順（10/24 の指示の 1）: **URL の規則（final: true）→ 題名の exclude → 題名の dialogue 引き上げ → 既定**（final でない URL の規則 → 区画の use）。
  指示の「URL の規則が先」をそのまま全部に当てると、総務課・企画 DX 課などを URL の規則で lookup にしたとき、題名の引き上げ（防災気象情報・ライドシェア）が効かない。
  そこで URL の規則は「既定を差し替える」だけにし、確定させたいもの（手続きナレッジの出典・求人の一覧・サイトの管理ページ）だけ `final: true` にした
- 題名の語は正規表現（`(?<![協審評])議会`・`(?<!求)人事`。「社会福祉協議会」「審議会」「求人事業主」を外さない）。exclude と引き上げの語が両方当たれば exclude
- パックの形式 2: `chunks.parquet` と LanceDB に `use` 列、`manifest.json` に `format: 2` と `use_counts`。exclude のページはパックに入れない
- `--from-cache-pack <版>`: キャッシュから組み直すときに前の版のページも戻す（江田島市のサイトがメンテナンス中で HTTP 500 だったので、江田島はキャッシュから組んだ）
- 迷い印（🔶）は 10/24 に確定したもの: 江田島の時刻表（124）は dialogue。atom/news・topics、安芸太田の RSS 3 本は lookup（題名の引き上げ語の記事は dialogue）。
  商工観光課・会計課・産業観光課・企画 DX 課・総務課・農業委員会・筒賀支所・/site/kyoiku/・移住・ふるさと納税・morica は lookup。夜回しで足したページは lookup

## B. 発話の型と、型ごとの検索の範囲

- `server/context/intents.yaml`（語）と `server/src/intents.py`（`classify_intent`・`nouns`）。優先 procedure > facility > event > tourism > weather > other > smalltalk。
  procedure は語に加えて、別名表（procedures.yaml）と手続きナレッジ（承認済み・下書き）の name・aliases で当たる。課の担当業務（handles）の語は見ない
  （商工観光課の「観光」で観光の問いが手続きになる）
- C の評価で直した: 下書き「観光案内」の別名「観光」「観光地」のように、**観光の語を含む名前・別名だけで当たったときは procedure にしない**（「江田島でおすすめの観光地」が procedure になり、
  観光バスツアーの補助金が付いていた）
- `KnowledgeConfig.scope_by_intent`（`IntentScope`）:

| 型 | 渡す資料 |
|---|---|
| procedure | 承認済みの手続きナレッジ＋固定事実。パックは渡さない。承認済みが無いときだけ dialogue の上位 2 ページ（同じページのチャンクは 1 件と数える）。名詞の足切りあり（10/24 の判断） |
| facility | 固定事実だけ |
| event | dialogue の上位 3 とお知らせ（WP11）の紹介する記事。名詞の足切りあり（「今週末」は具体的な日付にして当てる） |
| tourism | 渡さない。「調べてみましょうか？」の提案を優先（lookup はそのときに探す） |
| weather | 天気だけ |
| other | dialogue の上位 3。名詞の足切りあり |
| smalltalk | 渡さない |

- 名詞の足切り（B-2）: 発話の名詞（カタカナ 2 字以上・漢字 2 字以上・漢字 1 字＋送り仮名。助詞で始まる仮名は続けない）のどれかが、資料の題名か本文の先頭 200 字にあること
- 承認済みの手続きで答えたのに応答に課の名前が無ければ、規則で決まった担当の課を「担当は市民課（1階）です。」と一文足す（`ProcedureConfig.approved_department_sentence`。C の評価で直した）
- 毎ターンのログ: 「型: procedure / 渡した資料: 承認済み 1・パック 0・お知らせ 0」
- 「調べる」（lookup.py）: パック（dialogue と lookup）を先に探し、名詞の当たるものが無ければ許可ドメインへ
- テスト: `server/tests/test_wp13_unit.py`（型分け 35 例・優先・名詞・承認済みでパックなし・雑談/場所/観光/天気は検索しない・足切り・行事にお知らせ・観光で調べるの提案・
  調べるがパック先行・観光の別名・課の一文・ページで 2 件）、`kb/tests/test_scope.py`（決め方の順・引き上げ・final・区画の見当て・use 列・差分の組み直し）

## E. 用件の聞き分け（2026-10-24 追記）

指示は `docs/WP13_knowledge_scope.md` の E。実装は `server/src/clarify.py`（候補・問い・返事の判定）、`src/actions.py`（進行）、
`src/dialogue.py`（決まった 1 件だけで答える `forced_procedure`）、定型と語は `server/context/actions.yaml` の `clarify`、しきい値は `ProcedureConfig.clarify_*`。

### 決め方（LLM を使わない）

- **鍵**: 発話にある手続きの語（手続きナレッジの name・別名・`extra_words`、別名表の term・aliases）。ほかの鍵の中にある鍵は捨てる（「国保税」と言えば「国保」は鍵にしない）。
  手続きの語が無ければ発話の名詞（「手当」）。ただし候補を持つ名詞が 1 つだけのときで、一般の語（申請・手続き・相談・子ども…、`generic_nouns`）は使わない
- **候補**: 鍵を含む語（name・別名・when・extra_words）を持つ手続き（「国保」→ 国保の加入・国保の脱退・国保税）。`not_join` の語の中にあるだけなら数えない（「転入」⊂「転入学」）。
  別名表だけの手続き（国保税・児童扶養手当・特別児童扶養手当）は `term:<term>` で入る
- **聞く条件**: 1 つの鍵に候補が 2 件以上（その語そのものがあいまい）、全体で 2〜4 件、1 位と 2 位の点差が `clarify_margin`（1）未満。
  点は見分ける語（name を「の・・」で分けた語・別名・when・`cues`。鍵そのものは数えない）と、鍵が 2 つ以上のときは当たった鍵の数
  - 「国保に入りたい」→ 加入が「入り」で 1 点 → 聞かない。「国保の保険証をなくした」→ 脱退・保険証が鍵 2 つ → 聞かない。
    「子どもが生まれたので児童手当の申請」→ 鍵ごとの候補が 1 件ずつ（別々の手続きをはっきり言った）→ 聞かない
- 聞かないとき: 紹介状の聞き取りの途中（返事待ち全般）、深刻な打ち明け・迷子の定型の後と急いでいる語のある会話（`news_blocked`）、
  定型（代わりに申請・不満など）のターン、型が procedure でない発話、同じ候補の組をこの会話で聞いた後
- 問い: 「{鍵}のことですね。{A}か、{B}か、{C}か、どちらでしょう？」＋字幕だけの括弧書き「（1. A　2. B　3. C）」。読み上げは括弧を読まない（`speech_text`）。
  言い方は `labels`（国保に入る手続き・国保をやめる手続きや保険証・国保税…）、無ければ name の括弧書きを除いたもの。4 件以上なら上位 3 つ＋「ほかのこと」
- 返事: 順序の語 →「ほか」→ 見分ける語の点（1 位が 1 つだけなら決まり）。決まらなければ 1 回だけ「すみません、AかBか、どちらでしょう？」、
  それでも決まらなければ「手続きの詳しいことは、担当の課でご案内します。」＋紹介状の提案（担当課は未特定のまま、聞き取りなし）。
  元の問いの言い直し（文字 2-gram の重なり 0.6 以上）や、聞き直しの後の別の話には、聞き分けを閉じてふつうに答える
- 決まった後: その 1 件だけで答える（承認済みならその中身と課、下書き・別名表だけなら「担当の課でご案内します」）。短い返事（「二つ目」）は、LLM には
  「{言い方}のことです。」で渡す（おうむ返しで「二つ目ですね」と言ったので）。話題の手続きは決まった id で数える。紹介状の聞き取りは 1 問減らす（合わせて 3 問）
- 記録: 文字記録の案内役の行の `proposal.clarify` に「聞き分けの問い（候補 3 件: …）」「聞き分けた（候補 3 件 → kokuho_withdraw）」、
  来訪記録の `proposals` に `{"action": "clarify", "outcome": "<id>|未決|ほか", "candidates": "3"}`（本文は入れない）。返事待ちの間は既存の VAD・言語固定（段 `clarify`）
- 別名表に 児童扶養手当・特別児童扶養手当 を足した（両拠点とも課の handles にある語）。`intents.yaml` の procedure に「手当」「保険証」を足した

## 実機で見つかった不具合: 聞き分けの返事が紹介状の要約になった（2026-10-24）

職員パネルで紹介状の要約が「二番。」になっていた。原因は 2 つ:

- **要約の範囲**: 紹介状の要約は「提案のきっかけの発話から後」から作る（WP06）。聞き分けで決まったターンで紹介状を提案すると、きっかけが返事の「二番」になり、
  来訪者の言葉として「二番」だけが LLM に渡っていた（LLM が要約を返さないときは、きっかけの発話そのものが要約になる）
- **返事の判定**: 順序の語に「二つ目」「二番目」はあったが「二番」「2番」が無く、番号の字幕を見て言う「二番」が決まらなかった

直したこと:

- 聞き分けで決まったときは、要約の材料から返事（「二番」「やめるほう」）を外し、**聞き分けの前の来訪者の発話（「手当のことで」）と、決まった手続きの名前（「（用件: 児童扶養手当）」）**を渡す。
  LLM が要約を返さないときは「児童扶養手当のこと（手当のことで）」。LLM の要約に返事の語が入っていれば、その文を落とす。
  要約の範囲に返事のターンが入っているときだけ（後の別の話の紹介状に古い発話を混ぜない）。紹介状のタグは決まった手続きのタグを先に
- 来訪記録: 本文の要約は持たず、会話から選ぶタグに、決まった手続きのタグ（児童扶養手当なら子育て）を先に足す。
  文字記録: 来訪者の行は言ったとおり（「二番」）を残す（記録なので変えない）。案内役の行の `proposal.clarify` に「聞き分けた（候補 3 件 → term:児童扶養手当）」があるので、管理者は何に決まったか分かる
- 順序の語に「一番・二番・三番・四番」（漢数字・算用数字・全角）を足した。「一番困ってるのは税金で」のように順序でない「一番」もあるので、
  返事の判定は**見分ける語で 1 つに決まればそれを先に**、決まらないときだけ順序の語を見る順に変えた
- テスト: `server/tests/test_wp13_clarify.py`（要約に「二番」が入らない・LLM の要約から返事の語の文を落とす・来訪記録のタグ・「二番」の判定）。
  返事の判定の例に実機の「二番」など 3 件を足し、37 / 41（90%。手直しなしの例は 8 / 12 で変わらず）

## 英字の安全装置を「大文字の略語は 3 語まで」に（2026-10-24、実機確認から）

- 判定は `server/src/dialogue.py` の `foreign_tokens`（応答の 1 文ごと・お知らせの要約の 1 本ごと）。全角は NFKC で半角にして見る
  - 大文字だけの略語（英字 2〜5 字）は 1 応答（要約なら 1 本）に 3 語まで（`DialogueConfig.abbrev_max_per_reply`。同じ語は 1 つと数える）。4 語目から今までどおり言い直し→捨てる
  - 小文字・大文字小文字の混在の英単語（please・Thank you・6 字以上の大文字）は今までどおり（3 字以上で言い直し）
  - `server/context/allowed_terms.yaml`（Wi-Fi→ワイファイ、Web→ウェブ、km→キロメートル、kg→キログラム、cm→センチメートル、℃→ど）は数えず、
    読みを起動時に VOICEVOX のユーザー辞書へ（拠点の語と同じ経路）。拠点 YAML の `allow_ascii`（江田島の LINE）も数えない
  - 英字が 4 語以上（`english_words_min`）、またはピリオドで終わる英字の並び（英文）は、略語や allowed_terms の語でも言い直し→捨てる
- VOICEVOX の確認（辞書なし）: PDF→ピイディイエフ、QR→キュウアアル、LINE→ライン、ATM→エイティイエム、NHK・ETC・JR も字ごとに読む。
  辞書の登録後: Wi-Fi→ワイファイ、Web→ウェ'ブ、5km→ゴキロメエトル、10kg→ジュウキログラム、30cm→サンジュッセンチメエトル。
  **「℃」は辞書に登録しても効かず「ドシイ」と読む**（VOICEVOX が辞書より前に記号を読みに変える）ので、`allowed_terms.yaml` の `spoken: 度` で
  合成の直前に置き換える（20℃→ニジュウド）
- お知らせの要約: 職員パネルで引っかかったら理由に「英字: XXX（大文字の略語は 3 語まで、ほかは allowed_terms.yaml）」。
