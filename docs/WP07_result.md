## 1. 連絡方法が「電話」なら、番号がそろうまで保存しない

### 実機ログの「電話と答えたのに番号を聞かずに保存」の原因の候補

ログそのものは手元に無いので、コードからありうる道を 3 つ挙げて、全部を塞いだ。

| 道 | 何が起きるか | 直したこと |
|---|---|---|
| a. 連絡方法の答えが規則に当たらない | 「電話」が ASR で崩れる・どれにも当たらない・2 つに当たると「未定」で**すぐ保存**していた | 判定できないときは「お電話でよろしいですか？」と確かめる（はい → 番号を伺う。いいえ → 言った方法か未定で保存） |
| b. 番号を伺う段の答えが「言わない」の規則に当たる | 「大丈夫です」なども含む規則で、**番号なしで黙って保存**していた | 番号なしで保存し、「わかりました。お電話番号は窓口で伺いますね。」と言う |
| c. 番号が耳に届かない | 携帯やメモを見ながら番号を読むと顔が下を向き、WP02 の輪（正面が条件）から 3 秒で外れて、**発話が ASR に渡らない** | 紹介状の聞き取りの途中は、近くにいれば（PRESENT）正面でなくても聞く |

### 連絡方法の判定（`referral.contact_rules` を見直し）

| 方法 | 当たる言い方 |
|---|---|
| 電話 | 電話・でんわ・携帯・ケータイ・スマホ・TEL・かけて・折り返し・連絡して／連絡を／連絡ください… |
| 窓口で待つ | 待つ・待ちます・待っています・ここで待つ・窓口で・このまま・座って（**「ちょっと待ってください」は当たらない**。前の規則は「待」1 字で当たっていた） |
| 後日来庁 | 後日・また来・今度・あらため・改めて・明日・来週・別の日・出直 |

どれにも当たらない、または 2 つ以上に当たる（「電話か、また来るか」）ときは「お電話でよろしいですか？」。番号を言い始めていれば（数字があれば）電話。

### 電話のときの流れ

- 連絡方法が電話 → 「お電話番号を教えていただけますか？」 → 数字が 10〜11 桁にそろったら復唱（WP05 の連結のまま）
- 復唱に「違います」→ **1 回だけ**「もう一度、ゆっくりお願いします。」（前は番号を捨てて保存していた）
- そろわない（6 秒待って 1 回聞き直してもだめ）・言わない → 番号なしで保存し、「わかりました。お電話番号は窓口で伺いますね。」
- 連絡方法が電話でないのに、話の中で言っていた番号を復唱して「違います」なら、これまでどおり番号は控えずに保存
- 立ち去って会話が区切られた（待機タイムアウト・輪が解けて 8 秒）ときは、これまでどおり伺えたところまでで保存する（番号は無し）

## 2. 保存の後に、来訪者が触れた項目だけ伺い直す

- 紹介状を保存した会話の中で、来訪者が「電話番号」「名前」「住所」に触れたら（`referral.reopen_patterns`。「受付番号」は除く）、
  その項目だけ聞き取りを再開し（「失礼しました。お電話番号を教えていただけますか？」）、**同じ紹介状を書き直す**
  （`ReferralStore.update_contact`。電話番号を足したら連絡方法も電話に）。「受付番号○番の紹介状に書き足しました。」
- お名前を伺い直したときは確かめてそのまま書き足す（地区へは進まない）。お住まいも同じ
- 伺い直しは定型文で、LLM を通さない。WP05 の「聞き取りの外では、LLM が氏名・電話番号・住所を尋ねる文を捨てる」規則は
  そのまま（来訪者の側から触れたときだけの例外として、定型文で伺う）

## 3. 根拠の無い期限・金額・支払方法を言わない（`dialogue._ungrounded_claim`）

- 期限・金額・支払方法を言う文（「〜までに」「期限」「○日以内」「○円」「口座振替」「納付書」「振込」「コンビニ」「分割」「月末」…、
  `dialogue.money_deadline_pattern`）は、次の **両方** を満たすときだけ読み上げる
  1. 参考資料（または固定事実の開庁時間・補足・緊急連絡先）のどれかと、文字 2-gram の重なりが **0.3 以上**
  2. 文の中の **単位つきの数**（「1月31日」「200円」「14日以内」「5時」…）と **支払方法の語**（口座振替・納付書・コンビニ…）が、
     資料のどれかに **そのまま有る**
- 満たさなければその文を捨てて、代わりに「詳しい期限や金額は担当の課でご確認ください。」を 1 回だけ言う。捨てた後の、それを指す文
  （「この期限までに必ず納めてくださいね」）も読まない
- **2 の条件は作業指示に足した**。実機で試すと、「国民健康保険税の納期限は、毎年1月31日までです」が主語の語（国民健康保険税）だけで
  重なり 0.3 を超えた（日付は資料に無い作り話）。重なりだけでは、主題が合っていて値だけ作った文を止められない
- **読点で早めに切った 1 文目**（音声を早く始めるため）が期限・金額に触れていたら、続きと合わせてから判断する。前は頭の
  「国民健康保険税の納期限は、」だけが先に読まれ、続きを捨てると「納期限は、詳しい期限や金額は…」とつながった

### 実機での確認（LLM と知識パックで、同じ質問を 2 回ずつ）

| 質問 | 結果 |
|---|---|
| 国民健康保険税はいつまでに払えばいいですか | 「毎年1月31日までです」（資料に無い）を 2 回とも捨て、「詳しい期限や金額は担当の課でご確認ください」 |
| 住民票の写しはいくらですか | 「1通につき200円」「郵送料は110円」を読む（参考資料「戸籍・住民票などの郵便請求」の手数料の表に 200円 がある） |
| 軽自動車税の納付期限はいつですか | 「納付期限は4月1日です」を読んでしまう。資料（登録・廃車）の「4月1日」は課税の基準日で、**意味の取り違えは字面の照合では止められない** |
| 転出届はいつまでに出せばいいですか | 「14日以内」「30日以内」は資料にあるが、転入と転出を混ぜて言う（同上） |

評価セット 32 問では、この規則で捨てた文は無かった（期限・金額を作る問いが無い）。

## 4. 切り出し・沈黙・別れの一言を履歴に

- 切り出しは WP02 から履歴に積んでいた（来訪者の側は「（来訪者が目の前に来ました）」）
- **沈黙の一言と別れの一言**も、直前の応答の後ろに足す（`Conversation.note_assistant_line`。履歴が空なら切り出しと同じ形）。
  提案の聞き直し（WP02 E）は前から履歴に足していた
- LLM には案内役の発話として渡るので、同じ問いを繰り返しにくい。そのまま繰り返した文は既存の「これまでの応答と同じ文」で捨てる

## 6. カメラのデバッグ表示（追加の指示）

`/edge/debug` で画像が出なかった。ページが 300ms ごとに `<img>` の `src` を差し替えていたので、応答が 300ms より遅いと
（フロントの HTTP は ASR・TTS・LLM と同じイベントループで動く）、読み込みが終わる前に次の差し替えで中断され続け、いつまでも表示されない。
また、状態の取得で例外が出ると画像の更新ごと止まっていた。

- 画像は **1 枚ずつ順に** 取る（`fetch` を `cache: "no-store"` で → Blob の URL で表示 → 読み込みが終わってから 200ms 後に次）
- まだフレームが無い（404）・失敗したときは「まだ画像がありません（カメラのフレーム待ち）」などを出して 1 秒後にやり直す
- 状態（JSON）の取得は別のループにし、失敗しても画像の更新は止めない
- `/edge/debug.jpg` の配信はそのまま（`Cache-Control: no-store`）
